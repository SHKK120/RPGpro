# P0 — 첫 Godot 3D 화면 구현 지시서

대상: RPGpro
이 문서는 새로 제안하는 **P0 한정 시험안**이다.
사용자가 “start_P0.md를 읽고 P0 시험안으로 구현해”라고 지시한 경우에만 아래 구현을 수행한다.
읽기·검토만 요청받았다면 파일을 수정하지 않는다.
이 파일만으로 commit/push, P1, 최종 아트·전투 규칙의 확정을 승인받은 것은 아니다.

## 1. 목표와 승인 경계

목표는 하나다.
**기존 RPGpro 저장소에 실행 가능한 최소 Godot 3D 프로젝트를 만들고,
바닥·고정 카메라·조명·임시 물체가 표시되며 종료 후 다시 열리는지 확인한다.**

DOC-02의 “게임 코드/씬/project.godot를 만들지 않는다”는 제한은 문서 이관 작업의 범위였다.
이번 P0를 명시적으로 지시받으면 아래 프로젝트·씬 생성만 허용된다.
기존 지시서, instruction.md, 기록함 속 옛 지시를 연달아 실행하지 않는다.

P0 한정 선택:
- 렌더러: **Compatibility** (`gl_compatibility`). 첫 실행을 위한 임시 선택이다.
- 카메라: **원근 투영의 높은 사선 고정 시점**. 이동·회전·줌 조작 없음.
- 임시 표시물: 캡슐 하나와 서로 구별되는 상자 두 개. 캐릭터가 아니라 크기·깊이 확인용 물체다.
- 화면: 일반 해상도의 창 모드. 화면 전체 픽셀화·후처리 없음.
- 확인: 프로젝트 실행 → 실제 화면 확인 → 실행 종료 → 프로젝트를 다시 열고 재실행.

Compatibility에서 최종 시각 품질을 확정하지 않는다.
본격적인 바다·안개·물 효과와 에셋 채택 전에 Forward+ 등의 지원 여부와 표현 차이를 검토한다.
렌더러 변경이 무조건 무수정으로 된다고 기록하지 않는다.
최종 캐릭터 표현, P1 입력, 화면 픽셀화, 전투 방식은 계속 미정이다.

- 무관한 미추적 파일 때문에 작업을 중단할 필요는 없지만 읽기·수정·추적 대상으로 삼지 않는다.

`docs/41_P0_실행기반.md`를 한 장으로 만든다.
이미 있으면 실제 내용을 읽고 필요한 절만 보완한다.

다음만 담는다:
- P0 목표, 이번 임시 선택과 비목표.
- 실제 프로젝트/씬을 여는 방법.
- 아래 확인 목록.
- 직접 실행한 기술 확인 결과와 미확인 항목.

처음에는 모든 사람 확인 항목을 미확인으로 둔다.

| 확인 항목 | 안 되어야 하는 상황 |
|---|---|
| 실제 프로젝트를 실행하면 바닥·캡슐·상자 두 개가 보인다. | 에디터의 3D 미리보기만 보이거나, 실행 화면이 검게 비어 있다. |
| 물체의 형태와 앞뒤가 구별된다. | 물체가 바닥에 묻히거나 카메라 밖에 있다. |
| 실행을 종료하면 정상적으로 돌아온다. | 멈추지 않는 실행 창이나 오류가 남는다. |
| 프로젝트를 닫고 다시 열어 같은 메인 씬을 실행할 수 있다. | 메인 씬 지정이 사라지거나 참조 누락으로 실행되지 않는다. |
| 입력하지 않아도 구도가 유지된다. | 이동·카메라·게임플레이 기능이 임의로 추가돼 작동한다. |

색감·크기·각도는 P0의 가독성을 위한 임시 값이며 최종 아트 규격이 아니다.

## 4. 실제 구현 범위

### 새로 만들거나 필요한 부분만 수정할 구현 파일

1. `project.godot`
   - 기존 RPGpro 루트에 생성. 새 하위 저장소를 만들지 않는다.
   - 프로젝트 표시명 `RPGpro P0`는 개발용 임시 이름이다.
   - 메인 씬을 `res://scenes/prototype/p0_bootstrap.tscn`으로 지정한다.
   - Compatibility를 프로젝트에 명시한다.
   - 일반 창 모드로 띄운다. 1280×720은 P0 시험값으로 사용 가능하며 최종 규격이 아니다.
   - 필요 없는 설정·오토로드·플러그인·입력 액션을 추가하지 않는다.

2. `scenes/prototype/p0_bootstrap.tscn`
   - Node3D 루트.
   - 바닥 MeshInstance3D 하나.
   - 캡슐 MeshInstance3D 하나, 상자 MeshInstance3D 두 개.
   - 실제 DirectionalLight3D와 필요한 최소 WorldEnvironment.
   - 실제 실행용 Camera3D를 현재 카메라로 지정한다.
   - 에디터의 미리보기 태양/환경만으로 조명을 대신하지 않는다.
   - 엔진 내장 메시와 기본 재질을 사용한다. 외부 에셋은 받지 않는다.
   - 물리 시뮬레이션·플레이어 클래스·충돌·중력·이동은 이번에 필요 없다.
   - 정적인 씬으로 충분하므로 게임 스크립트를 만들지 않는 것을 우선한다.
   - 크기·변환·재질 값은 이 시험 씬이 소유한다. 별도 설정 프레임워크를 만들지 않는다.
   - 무작위 UID나 없는 에셋 참조를 만들어 넣지 않는다.

3. `.gitignore`
   - 기존 내용을 보존하고 필요하면 `.godot/` 캐시 제외만 추가한다.
   - 기존 문서·지시서·소스 파일을 숨기기 위해 광범위한 패턴을 추가하지 않는다.
   - .tscn/.tres/.uid 전체를 캐시로 취급해 제외하지 않는다.
   - LFS·Git 플러그인·전역 Git 설정을 도입하지 않는다.

엔진이 자동 생성한 파일과 Codex가 의도적으로 작성한 파일을 보고에서 구분한다.
장면 재저장으로 생긴 엔진 관리 정보가 있으면 임의 삭제하지 말고 실제 목록을 보고한다.

## 6. Codex가 실제로 확인할 것

새 검사 프레임워크나 검토 에이전트는 만들지 않는다. 검토 에이전트 0.
사용 중인 엔진의 `--help`와 로컬 문서에 맞는 명령을 사용한다.

- 프로젝트·씬의 참조와 로드 오류를 확인한다.
- 허용된다면 headless import와 메인 씬의 짧은 로드 실행으로 파싱/실행 오류를 확인한다.
  `--headless --import`, `--headless --path ... --quit-after ...` 등을 현재 실행 파일 지원에 맞게 사용한다.
  `--quit-after`는 프레임/반복 횟수이며 초 단위 타이머라고 기록하지 않는다.
- 위 확인은 그래픽 드라이버·실제 화면 표시 검증을 대신하지 못한다.
- 허용되는 환경이면 GUI 에디터/실행을 열어 로그를 확인하고, 사람이 화면을 볼 수 있게 안내한다.
- GUI 실행이 차단되면 시스템 설정 변경이나 무한 재시도를 하지 않는다.
  파일 생성 결과, 실행한 명령, 오류를 구분해 보고하고 사람의 일반 Godot 실행 확인으로 넘긴다.
- Renderer 실패를 이유로 허락 없이 엔진 업데이트·드라이버 설치·관리자 실행·보안 해제를 하지 않는다.
- 코드/씬 오류는 이번 허용 범위 안에서 수정한다. 환경 문제와 작성 오류를 혼동하지 않는다.
- 직접 보지 못한 화면, 사람의 버튼 조작, 재실행 결과를 확인 완료로 적지 않는다.

사람에게 안내할 실행 방법:
- Godot 프로젝트 관리자에서 기존 RPGpro의 `project.godot`를 가져와 열거나,
  확인된 Godot 실행 파일을 `--editor --path`와 함께 실행한다.
- 프로젝트 실행 버튼/F5로 메인 씬을 실행한다.
- 정지 버튼/F8로 실행을 멈춘다.
- 에디터를 닫았다가 같은 프로젝트를 다시 열고 재실행한다.
- 사용자 파일 편집이나 노드 수동 배치를 요구하지 않는다.

## 7. 하지 않을 것

P1, 이동, 전투, 채집, 집, 가구 시스템, 저장, 바다 셰이더, Vista 전환, 낮밤,
멀티, Steam, Meshy/Higgsfield, UI 프레임워크, 네트워크·데이터 범용 구조,
검토 서브에이전트, 설치·보안 변경, reset/clean/강제 push.

`docs/기록함/모델 설정.md`, 다른 지시서와 기존 미추적 파일을 수정·삭제·추적하지 않는다.

## 8. 완료 보고 후 중단

1. 현재 루트, 사용한 Godot 실행 파일/실제 버전.
2. 새로 만든 파일·수정한 파일·엔진 자동 생성 파일.
3. 이번에 선택한 P0 시험 설정과 미정으로 남긴 P1/최종 규칙.
4. 실제 실행한 명령·출력의 핵심, 오류와 수정 결과.
5. 사람에게 열어볼 프로젝트·씬, 남은 확인 목록.
6. 40의 현재 상태와 새 장부 항목.
7. 실제 Git 상태. 이번 구현은 commit/push하지 않았으며 원격 미보존임을 명시.

사람 확인 전 P0 통과로 쓰지 않는다.
P1로 자동 진행하지 않는다.
commit/push는 후속 명시적 승인이 있어야 한다.
