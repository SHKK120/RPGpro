# P0 마무리 — 사람 확인 반영 및 첫 구현 보존

대상: RPGpro
목적: 사용자가 직접 확인한 P0 결과를 기록하고, 지정된 P0 파일만 원격에 보존한다.
게임 기능 추가나 P1 구현 지시가 아니다.

## 실행 조건

이 파일만 읽었다고 사람 확인 또는 commit/push가 승인된 것은 아니다.

사용자가 직접 아래 내용을 확인한 뒤
`finish_P0.md를 읽고 P0 사람 확인 완료, 백업 승인.`
이라고 지시했을 때만 기록과 보존을 진행한다.

사람이 확인할 내용:
- 프로젝트 실행 버튼/F5로 바닥, 캡슐 하나, 상자 두 개가 보인다.
- 형태와 깊이가 구별되고, 입력하지 않으면 구도가 유지된다.
- 정지 버튼/F8로 실행이 정상 종료된다.
- 에디터를 닫고 같은 프로젝트를 다시 연 뒤 실행해도 같은 화면이 나온다.
- 위 실행과 종료를 막는 새 오류가 나타나지 않는다.

확인되지 않았거나 실패한 항목은 통과로 기록하지 않는다.
사용자가 확인이나 백업 승인을 하지 않았으면 읽기와 남은 항목 안내만 하고 멈춘다.
이 파일의 작성 시점에는 ChatGPT가 스크린샷의 표시 상태만 검토했다.
사용자의 종료·재실행 확인을 미리 수행된 사실로 간주하지 않는다.

## 1. 현재 상태 확인

AGENTS.md → docs/00_시작.md → docs/40_구현순서.md를 읽는다.
docs/41_P0_실행기반.md와 지시장부의 최근 P0 기록을 확인한다.
보존 대상 파일은 실제 내용과 참조를 읽는다. 과거 문서를 통째로 다시 검토하지 않는다.

보고된 정보:
- 루트: C:\Users\CKIRUser\RPGpro
- 기준 HEAD: 663ac9611349a44799b726d584d5f33baed2594f
- 원격 목적지: github.com/SHKK120/RPGpro
- 대상 브랜치: main
- P0 장부: 008
- P0는 구현완료·사람확인대기이며 아직 commit/push하지 않은 상태였다.

현재 루트·브랜치·원격 목적지·변경 목록·staged 목록을 다시 확인한다.
토큰이 들어 있을 수 있는 원격 URL이나 인증 설정은 출력하지 않는다.
번호와 HEAD는 확인 후보이며, 달라졌다는 이유로 reset하지 않는다.
다른 저장소·브랜치거나 무관한 staged 변경이 있으면 자동 변경하지 말고 보고한다.
동일한 P0 보존이 이미 완료돼 있으면 중복 기록·빈 커밋을 만들지 않는다.

## 2. 사람 확인 기록 — 세 문서만 필요한 부분 수정

수정 허용:
- docs/41_P0_실행기반.md
- docs/40_구현순서.md
- docs/지시장부.md

41:
- 실제 사용자 보고가 있는 항목만 사람 확인 완료로 기록한다.
- 기술 확인, ChatGPT의 이미지 검토, 사용자의 실제 실행 확인을 구분한다.
- 스크린샷 검토 내용: 바닥·캡슐 하나·상자 두 개·형태·그림자 표시를 확인.
- 새 스크린샷이나 실행 로그를 생성·위조하지 않는다.
- 사람이 확인한 성공은 P0 실행 기반에 한정한다. 성능·최종 아트·게임 재미는 미검증이다.

40:
- 위 사람 확인 항목을 모두 확인받았으면 `P0 — 사람 확인 통과 (실행 기반)`으로 기록한다.
- 다음 행동은 P1-1의 최소 이동 시험안을 별도로 승인받는 것이라고 기록한다.
- P1 입력, 최종 캐릭터와 아트, 최종 렌더러를 확정하지 않는다.
- 아직 수행하지 않은 push를 성공으로 미리 기록하지 않는다.
  커밋 ID와 실제 원격 반영 여부는 이번 완료 보고에 남긴다.

장부:
- 실제 다음 번호를 사용한다.
- 기존 여섯 항목 형식으로 사용자 확인과 이번 보존 범위를 기록한다.
- 과거 기록의 미확인을 소급해서 직접 확인으로 바꾸지 않는다.
- 검토 에이전트 0.

기존 headless Movie Maker 실패는 테스트 경로의 실패로 남긴다.
정확한 엔진 충돌 원인이 해결됐다고 쓰지 않는다.
이번에는 영상 출력·추가 자동 촬영·Movie Maker 재시도·새 검사 프레임워크를 만들지 않는다.

## 3. 보존 범위 — 아래 실제 P0 파일 9개만

```text
project.godot
scenes/prototype/p0_bootstrap.tscn
.gitignore
docs/41_P0_실행기반.md
docs/00_시작.md
docs/01_환경복구.md
docs/40_구현순서.md
docs/50_닫을것.md
docs/지시장부.md
```

위 목록 중 구현 파일과 설정 파일은 내용 확인·stage만 허용한다.
이사·이동·충돌 등 새 기능을 보태거나 프로젝트를 다시 생성하지 않는다.

필수 참조 파일이 목록 밖에 있다면 목록을 자동 확대하지 말고 경로와 필요성만 보고한다.
없는 파일을 백업을 위해 지어내지 않는다.

제외:
- .godot/ 캐시, 영상, 임시 렌더 출력·덤프·로그
- docs/기록함/모델 설정.md
- instruction.md의 기존 삭제 변경
- 이번 finish_P0.md 및 기존 작업과 무관한 지시서
- docs/기록함/지시서/ 아래 승인 목록에 없는 새 파일
- 개인 세이브, 인증 정보, 계정 캐시, 외부 에셋 원본

instruction.md의 삭제는 이번 보존 대상이 아니다.
복구·재삭제·stage하지 않고 기존 작업 트리에 남긴다.
이 때문에 보존 후 Git 상태가 깨끗하지 않아도 무관한 파일을 정리하지 않는다.

## 4. 승인 후 보존

1. 지정 9개 파일의 실제 변경을 확인한다.
   미추적 파일은 일반 diff에 없다고 검토를 생략하지 않고 읽는다.
   명백한 비밀값이나 무관한 내용 혼입이 보이면 값은 출력하지 말고 경로와 종류만 보고한다.
2. 승인된 9개 경로만 명시적으로 stage한다.
   `git add .`, `git add -A`, `git add docs/` 등 전체 추가를 하지 않는다.
3. staged 목록과 내용을 확인한 뒤 P0 checkpoint 커밋을 만든다.
   메시지 예: `feat: checkpoint P0 3D bootstrap`
4. 확인된 origin/main에 일반 push한다.
   force push, reset, clean, rebase, 자동 병합, 작성자·인증·원격 설정 변경은 하지 않는다.
   인증이나 원격 이력 문제로 실패하면 해당 사실과 현재 보존 상태를 보고하고 멈춘다.
5. push 결과 및 대상 원격 브랜치 커밋을 확인하고 로컬 HEAD와 비교한다.
   로컬 로그나 예전 origin/main 값만으로 이번 업로드 성공을 주장하지 않는다.
   조회 불가나 불일치는 그대로 보고한다.
6. 보고 후 멈춘다. P1 또는 추가 기능으로 자동 진행하지 않는다.

## 완료 보고

- 사용자 확인으로 통과한 범위와 아직 미검증인 범위.
- 이번 문서 수정·실제 커밋 대상 파일.
- 로컬 커밋 ID / 대상 원격 브랜치 / 확인한 원격 커밋 ID와 일치 여부.
- 남은 staged 변경과 제외된 수정·삭제·미추적 항목.
- 다음 행동: 별도 승인으로 P1-1 최소 이동 시험.

이 작업은 첫 실행 기반을 보존하는 것이다.
게임의 최종 성능, 아트, 보스, 저장, 멀티플레이는 이번에 검증하거나 구현하지 않는다.
