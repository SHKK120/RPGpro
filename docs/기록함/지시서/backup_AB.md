A·B 문서 중간 보존 — 준비와 승인 후 실행

대상: RPGpro
목적: DOC-02의 A·B 결과와 기존 문서 뼈대를 잃지 않도록 원격 보존한다.
이 파일은 게임 기획 이관이나 C단계 실행 지시서가 아니다.

기본 동작은 준비 확인만이다. 파일을 읽거나 이 파일을 전달받은 것만으로 commit/push를 승인받은 것이 아니다.
준비 결과에서 사용자가 대상 저장소와 파일 목록을 확인한 뒤 **“A·B 문서 백업 승인”**이라고 별도로 지시했을 때만 아래 2단계를 실행한다.
C~E, 게임 코드, 엔진 설정, 새 도구 설치, 계정 인증 변경은 수행하지 않는다.

1. 준비 확인 — 기본 실행 범위

AGENTS.md, docs/00_시작.md, docs/40_구현순서.md, docs/지시장부.md의 필요한 최근 항목을 읽는다. 이 지시의 보존 후보를 확인하는 데 필요한 파일만 추가로 읽는다.

실제 저장소 최상위 경로, 브랜치, 미커밋·미추적·이미 staged 된 파일을 확인한다. 지난 보고의 경로는 C:\Users\CKIRUser\RPGpro, 브랜치는 main, 원격 이름은 origin이었지만 현재 상태를 다시 확인한다.

origin의 실제 목적지를 안전하게 확인한다. 보고에는 호스트와 소유자/저장소명만 표시하고, 토큰·비밀번호가 들어 있을 수 있는 URL 원문이나 인증 설정은 출력하지 않는다. 안전하게 확인할 수 없으면 미확인으로 표시한다.

A와 B의 작업 기록, 40의 현재 상태가 있는지 확인한다. 없는 기록을 수행한 것처럼 만들어 넣지 않는다. B의 네 본문에 대한 ChatGPT 문서 검토 의견은 '이번 이관 지시와 일치하며 필수 수정 없음'이다. 이는 게임 플레이 통과나 [제안]을 [요구·채택 방향]으로 승인했다는 뜻이 아니다.

아래 후보 중 실제 있는 파일의 상태를 확인한다. 미추적 파일은 Git diff만으로 검토가 끝났다고 하지 말고 파일 자체를 읽는다. 코드·바이너리·생성 원본·개인 세이브·인증 파일을 보존 후보에 섞지 않는다.

문서에 실제 비밀값이나 개인 인증 정보가 포함돼 있지 않은지 후보 범위 안에서만 확인한다. '토큰을 저장하지 않는다' 같은 규칙 문장을 비밀 유출로 오인하지 않는다. 문제가 보이면 값 자체를 재출력하지 말고 해당 경로와 문제 종류만 보고한다.

현재 내용과 경로가 예상과 다르거나 무관한 staged 변경이 있으면 사실을 보고한다. 자동으로 unstage/reset/삭제하지 않는다. 업로드 파일명의 (1)·(2)만 보고 로컬 파일을 개명하지 않는다.

2. 승인 후 보존 — 별도 지시가 있을 때만

사용자가 위 준비 결과의 대상 저장소와 파일 목록을 확인하고 A·B 문서 백업 승인이라고 명시한 경우에만 수행한다. 대상이 미확인되었거나 별도 위험이 남아 있으면 해당 문제를 먼저 한 번 확인한다.

준비 확인 이후 작업 경로·원격 목적지·변경 범위가 달라지지 않았는지 확인한다. 달라졌으면 새 대상을 조용히 포함하지 말고 보고한다.

현재 40과 장부에 이번 문서 검토·보존 작업의 사실을 최소 기록한다. 번호는 실제 다음 번호를 쓴다. A·B는 문서 이관 상태로만 관리하고 게임 기능은 통과 처리하지 않는다. 제안과 미정의 상태를 바꾸지 않는다.

아직 push하지 않은 문서에는 원격 보존을 완료했다고 미리 쓰지 않는다. 커밋에 자기 자신의 해시를 넣으려 하지 않는다. 실제 커밋 ID와 원격 확인 결과는 완료 보고에 남긴다.

승인된 문서 파일 경로만 명시적으로 stage한다. git add ., git add -A, git add docs/ 같은 일괄 추가는 하지 않는다. 무관한 staged 변경을 자동으로 해제하거나 함께 커밋하지 않는다.

staged 파일 목록과 변경 내용을 확인하고 문서 checkpoint 커밋을 만든다. 작성자 정보나 인증이 없어 막히면 이유만 보고한다. 작성자 정보·원격 설정·인증 설정을 임의로 생성하거나 바꾸지 않는다.

승인된 origin의 확인된 브랜치에 일반 push를 한다. force push·reset·clean·rebase·자동 병합은 하지 않는다. 원격에 별도 커밋이 있어 거절되면 보고 후 멈춘다.

push 출력과 대상 원격 브랜치의 커밋 ID를 확인한다. 로컬 HEAD와 일치한 것이 확인될 때만 이번 checkpoint의 원격 반영을 확인했다고 보고한다. 로컬 로그만 보고 원격 보존 성공이라고 하지 않는다. 원격 조회가 불가능하면 미확인으로 남긴다.

C단계로 자동 진행하지 않는다. 게임 코드·Godot 프로젝트 생성·에셋 제작은 하지 않는다.

중단과 실패

준비 확인이나 업로드가 실패해도 게임 파일이나 문서를 임의로 복구하지 않는다. 권한 우회, 보안 설정 변경, 새 도구 설치를 시도하지 않는다. 비밀값을 사용자에게 붙여넣게 하지 않는다. 이 절차는 프로젝트 문서 보존이지, Godot의 플레이 세이브나 PC 전체 백업이 아니다.
