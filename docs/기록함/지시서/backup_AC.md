# A~C 문서 중간 보존 — 준비 확인 / 승인 후 실행

대상: RPGpro
목적: DOC-02 A~C까지 작성된 현재 문서와 기존 뼈대를 원격에 보존한다.
이 파일은 이전 `backup_AB.md`를 대체한다. 두 보존 지시서를 연달아 실행하지 않는다.

> 기본 실행은 **준비 확인만**이다. 파일 수정, stage, commit, push를 하지 않는다.
> 사용자가 대상 저장소와 파일 목록을 확인한 뒤 **“A~C 문서 백업 승인”**이라고 별도로 지시하면 승인 후 보존을 실행한다.
> 문서 백업은 기획 승인이나 구현 통과가 아니다. C의 본문 검토대기 상태를 그대로 유지한다.
> D~E, 게임 코드, 엔진 설정, 외부 에셋 작업은 진행하지 않는다.

## 1. 준비 확인 — 지금 수행할 범위

1. `AGENTS.md`, `docs/00_시작.md`, `docs/40_구현순서.md`, `docs/지시장부.md`의 필요한 최근 기록을 읽는다.
2. 실제 저장소 최상위 경로, 브랜치, 미추적·수정·이미 staged 된 파일을 확인한다.
   과거 보고의 경로는 `C:\Users\CKIRUser\RPGpro`지만 실제 결과와 구분한다.
3. `origin`의 목적지를 확인한다. 보고에는 호스트와 소유자/저장소명만 표시한다.
   토큰·비밀번호가 들어 있는 URL 원문이나 인증 설정은 출력하지 않는다.
   안전하게 확인하지 못하면 미확인으로 보고한다.
4. 보고된 작업 이력은 A=001, B=002, C=003이다. 실제 장부에서 확인하고 없는 기록을 지어내지 않는다.
   - A: 작업 보고가 검토된 상태.
   - B: 10~13 네 문서 본문과 작업 보고가 검토된 상태.
   - C: 작업 보고만 확인됐으며, 외부에서 최신 네 본문을 검토한 것으로 기록하지 않는다.
   - 문서 이관 적합은 제안의 확정이나 실제 게임의 통과를 뜻하지 않는다.
5. 아래 후보 중 실제 존재하는 파일을 열어 내용과 상태를 확인한다.
   미추적 파일은 일반 diff에 없다고 검토를 생략하지 않는다.
   확인은 경로, 읽기 가능 여부, 명백한 비밀값·무관한 파일 혼입 등 보존 준비에 한정한다.
   게임 기획을 재설계하거나 별도 검토 에이전트를 실행하지 않는다.
6. 예상 밖의 staged 변경이나 파일 손상이 보이면 경로와 문제 종류만 보고한다.
   자동으로 unstage, 삭제, reset, 복구하지 않는다.
7. 기존 미커밋 변경은 보존한다. C 문서를 뼈대로 되돌리거나 옛 A·B 상태로 바꾸지 않는다.

## 2. 승인 후 보존 — 지금 자동 실행하지 않음

위 목적지와 목록에 대해 사용자가 `A~C 문서 백업 승인`이라고 지시한 경우에만:

1. 준비 이후 대상 저장소와 변경 범위가 달라졌는지 확인한다.
   달라졌으면 이전 승인을 새 대상에 자동 적용하지 않고 보고한다.
2. 승인된 40과 장부에 이번 보존 작업의 사실을 최소 기록한다.
   C는 본문 검토대기를 유지하고, 제안·미정·D~E 상태는 바꾸지 않는다.
   아직 실행하지 않은 push의 성공을 미리 기록하지 않는다.
3. 승인된 파일 경로만 명시적으로 stage한다.
   `git add .`, `git add -A`, `git add docs/` 같은 일괄 추가는 하지 않는다.
   무관한 staged 변경이 있으면 함께 커밋하거나 자동 해제하지 말고 보고한다.
4. staged 목록과 내용을 확인하고 문서 중간 보존 커밋을 만든다.
   메시지 예: `docs: checkpoint DOC-02 A-C (C pending content review)`
   작성자 정보나 인증이 없어 막히면 보고한다. Git 설정·인증을 임의로 변경하지 않는다.
5. 승인된 원격의 확인된 브랜치로 일반 push한다.
   force push, reset, clean, rebase, 자동 병합은 하지 않는다.
   원격 이력 차이 등으로 거절되면 오류 종류와 현재 보존 상태를 보고하고 멈춘다.
6. push 출력과 대상 원격 브랜치의 커밋 ID를 확인한다.
   로컬 HEAD와의 일치 여부를 보고한다. 확인 불가나 불일치를 성공으로 쓰지 않는다.
   커밋 안에 그 커밋 자신의 해시를 적으려 하지 않는다.
7. 완료 보고에 커밋 범위, 로컬/원격 커밋 ID, 원격 반영 여부, 제외한 파일을 남긴다.
8. D로 자동 진행하지 않는다. 보고 후 멈춘다.
