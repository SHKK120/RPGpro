# A~C 문서 보존 — 검토 결과 반영 및 승인 조건

대상 프로젝트: RPGpro
대상 저장소: github.com/SHKK120/RPGpro
대상 브랜치: main / 원격 이름: origin

이 파일은 새 게임 기획이나 새 백업 체계가 아니다.
이미 수행한 `backup_AC.md`의 준비 결과에, 그 이후 받은 문서 검토 결과를 반영하는 승인 조건이다.
파일을 다운로드하거나 읽는 것만으로 원격 쓰기가 승인되지는 않는다.
사용자가 이 파일을 지정하여 **A~C 문서 백업을 승인**하면 아래 범위로 실행한다.

## 먼저 적용할 변경 — 과거의 C 검토대기 유지 지시보다 우선

- ChatGPT는 이번에 제공된 C의 네 본문(14, 15, 31, 32)을 검토했고, DOC-02 / C의 문서 이관 기준에서 필수 수정이 없다고 판단했다.
- B의 네 본문은 앞서 검토됐고, 이번에 재제공된 11과 12도 확인했다.
- 따라서 `backup_AC.md`의 “C 본문 검토대기를 유지한다”는 부분만 이번 결과로 대체한다.
- B와 C는 **외부 본문 검토 적합 — 문서 이관**으로 기록할 수 있다.
- 이는 [제안]을 확정하거나 게임 기능·실제 플레이·시각 만족·재미를 통과 처리한다는 뜻이 아니다.
- A의 기존 상태는 유지한다. D~E는 미수행으로 남긴다.
- 40과 장부의 최신 본문, Git 상태 및 원격 목적지는 ChatGPT가 직접 접속하여 검증한 것이 아니라 사용자가 전달한 Codex 보고를 기준으로 한 정보다.

## 승인 후 실행

1. AGENTS와 00, 40, 장부의 필요한 최근 기록을 읽는다. 기존 준비에서 확인한 작업 경로·원격 목적지·브랜치·파일 범위가 달라지지 않았는지 재확인한다. 기획 전체를 재검토하거나 새로운 준비 문서를 만들 필요는 없다.
2. 대상이 달라졌거나 무관한 staged 변경이 생겼으면 자동 포함·해제하지 말고 한 번 보고한다. 인증 정보는 출력하지 않는다.
3. `docs/40_구현순서.md`와 `docs/지시장부.md`에 위 B·C 문서 검토 결과와 실제 보존 작업을 최소 기록한다. 장부 번호는 실제 다음 번호를 사용한다. 과거 지시서 보관본은 수정하지 않는다.
4. 아직 하지 않은 push를 완료했다고 미리 기록하지 않는다. 자기 커밋의 해시를 그 커밋 안에 넣으려 하지 않는다. 실제 커밋 ID와 원격 확인 결과는 최종 보고에 남긴다.
5. 승인된 21개 파일 경로만 명시적으로 stage한다. `git add .`, `git add -A`, `git add docs/`는 쓰지 않는다. staged 목록을 확인한 뒤 문서 중간 보존 커밋을 만든다.
6. 확인된 origin/main에 일반 push하고 로컬 HEAD와 대상 원격 브랜치 커밋의 일치 여부를 확인한다. 원격 확인 불가를 성공으로 쓰지 않는다.
7. 인증·작성자 설정 부족이나 원격 이력 차이로 막히면 현재 보존 상태와 원인만 보고한다. 강제 push·reset·clean·rebase·자동 병합·무단 설정 변경은 하지 않는다.
8. 원격 보존이 확인되더라도 D로 자동 진행하지 않는다. 보고 후 멈춘다.

## 제외 파일과 보존 상태

- `instruction.md`: 이번 수정·stage 대상에서 제외한다. 이미 추적되는 파일의 기존 이력을 지우라는 뜻은 아니다.
- `docs/기록함/모델 설정.md`: 검토 및 승인 목록 밖이다. 수정·삭제·stage하지 않는다.
- `approve_AC.md`, `backup_AC.md`, `backup_AB.md` 등 루트 또는 Downloads의 임시 지시서: 새로 stage하거나 보관본을 추가하지 않는다.
- 게임 코드·씬·리소스·에셋·project.godot·개인 세이브·계정 인증 파일은 대상이 아니다.
- 제외한 미추적 파일이 남아 있어도 승인 문서의 보존 여부와 구별한다. 저장소를 깨끗하게 만들려고 삭제하거나 추가 커밋하지 않는다.
- 이번 보존은 승인 문서의 현재 상태에 대한 것이며, 게임 전체나 PC 전체의 백업이 아니다.
