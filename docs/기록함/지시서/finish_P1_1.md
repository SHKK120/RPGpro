# P1-1 마무리 — 사용자 확인 기록 및 최소 이동 보존

대상: RPGpro
목적: 사용자가 확인한 최소 이동 시험 결과를 기록하고, 현재 P1-1 구현을 원격에 보존한다.
새 기능 구현, 충돌 방식 변경, 그래픽 경고 수정 지시가 아니다.

권장 모델·추론: 선택 목록에 있는 GPT-5.6 Sol + Medium.
이번 작업은 문서 갱신과 한정된 Git 보존이므로 추가 검토 에이전트는 0개다.
모델·앱 설정은 사용자가 선택하며, 이 지시를 이유로 설정 파일을 자동 수정하지 않는다.

## 1. 실행과 승인 경계

사용자가 다음처럼 명시적으로 지시했을 때 기록과 commit/push를 진행한다.

`finish_P1_1.md를 읽고 P1-1 사람 확인 반영, 백업 승인.`

읽기·검토만 요청받았다면 파일 수정·stage·commit·push를 하지 않는다.
이 파일은 P1-2 우클릭 이동, 경로 탐색, 카메라 추적, 최종 조작 방식의 승인이 아니다.
이전 구현·백업 지시서를 연달아 재실행하지 않는다.

## 2. 이미 전달된 확인 결과 — 같은 테스트를 다시 요구하지 않는다

아래는 이 대화에서 전달된 사용자 보고의 요약이다. Codex가 직접 실행한 것으로 바꾸지 않는다.

- WASD 이동을 테스트했다.
- 물체나 벽을 향하면 그 안쪽으로 진행하지 못하며, W+A를 유지하면 벽을 따라 부드럽게 이동한다.
- 벽 슬라이딩은 덜덜 떨거나 튕기는 현상으로 보고되지 않았다.
- 키를 놓으면 수평 이동이 멈춘다.
- 외곽 모서리에서 바닥 밖으로 빠지지 않는다.
- 고정 카메라, 재실행, P0 비교가 가능함을 확인했다.
- 표시된 그래픽 메시지는 OpenGL 3.3 드라이버 품질과 ANGLE 전환에 관한 기존 경고다. 이 메시지가 있어도 위 조작 확인은 진행됐다.

기존 P1-1 기술 완료 보고:
- import·GDScript 파싱, 메인 씬 headless 로드, 일반 Compatibility 실행 성공.
- 카메라 참조, 입력 액션, 충돌 노드와 대각선 속도 제한을 확인했다고 보고됨.
- P0 원본 씬은 변경하지 않았다고 보고됨.

구분:
- 이번 사용자 보고에 근거해 `P1-1 — 사람 확인 통과 (최소 이동)`으로 기록할 수 있다.
- 이는 기본 조작·정지·충돌·카메라·재실행의 수용이다. 모든 상황의 무결함을 보증하지 않는다.
- 대각 속도를 사람이 수치로 실측했다거나 프레임 성능을 측정했다고 쓰지 않는다.
- 기술 검증은 기존 기술 보고로, 체감 동작은 사용자 보고로 나눈다.
- 최종 캐릭터·이동 방식·아트·렌더러, 성능·재미, 우클릭·경로 탐색은 미검증/미정으로 유지한다.
- ChatGPT가 현재 P1 소스 전체를 직접 읽어 검증했다고 기록하지 않는다.

원격 보고에는 호스트와 소유자/저장소명만 쓰고, 토큰·비밀번호가 있을 수 있는 URL·인증 설정은 출력하지 않는다.
HEAD가 다르다는 이유로 reset하지 않는다. 같은 보존이 이미 끝났으면 중복 기록·빈 커밋을 만들지 않는다.
다른 저장소·브랜치 또는 무관한 staged 변경이 있으면 자동으로 바꾸거나 해제하지 말고 보고한다.
사용자 테스트 후 구현이 변경된 정황이 있으면 이전 확인을 새 구현에 자동 적용하지 않고 그 차이만 알린다.

- 사용자 확인과 기존 Codex 기술 확인을 구분한다. 새 로그·스크린샷·벤치마크 결과를 만들지 않는다.

조건부 후보:

`docs/01_환경복구.md`가 기존 P1-1 구현에서 이미 수정됐고, 변경이 P0 고정 안내를 현재 메인 씬 참조로 바로잡은 최소 보완임을 확인하면 함께 보존할 수 있다. 이번 마무리에서는 추가 수정하지 않는다. 다른 변경이 섞였으면 자동 포함하지 말고 보고한다.

후보의 존재·변경을 실제로 확인하고, 실제 stage·커밋한 파일 수를 센다.
바뀌지 않은 파일을 억지로 수정하지 않는다. UID는 엔진이 실제 생성한 파일을 보존하며 값을 지어내지 않는다.
project.godot·씬·스크립트·UID는 읽기와 stage만 허용한다. 리팩터링·자동 재저장·코드 수정은 하지 않는다.
누락된 필수 참조나 예상 밖 소스 변경이 있으면 자동으로 목록을 확대하거나 복구하지 말고 보고한다.

### 제외 및 유지

- `scenes/prototype/p0_bootstrap.tscn`: 보존된 원본이며 이번에 수정하거나 stage하지 않는다.
- `.godot/`와 임시 렌더·영상·크래시 덤프·로그.
- `instruction.md`의 기존 삭제 변경: 복구·재삭제·stage하지 않는다.
- `docs/기록함/모델 설정.md`, 승인 목록 밖 기록함의 지시서.
- 이번 `finish_P1_1.md`와 다른 임시 실행 지시서.
- 개인 세이브·인증 파일·계정 캐시·외부 에셋 원본.

제외한 변경이 남는 것은 허용한다. 작업 트리를 깨끗하게 보이게 하려고 임의 삭제·추가하지 않는다.

## 6. 승인 후 보존 절차

1. 보존 후보의 diff와 미추적 파일 본문을 확인한다. 문서·소스 참조, 명백한 비밀값이나 무관한 변경 혼입만 한정 점검한다. 새로운 검사 프레임워크나 반복 그래픽 테스트를 만들지 않는다.
2. 사용자 테스트 이후 구현을 바꾸지 않은 상태에서, 승인 후보 중 실제 필요한 파일 경로만 명시적으로 stage한다.
   `git add .`, `git add -A`, `git add docs/`처럼 광범위하게 추가하지 않는다.
3. staged 목록과 내용을 확인해 P1-1 checkpoint 커밋을 만든다.
   메시지 예: `feat: checkpoint P1-1 basic movement`
4. 확인된 origin/main에 일반 push한다. 작성자·인증·remote·전역 Git 설정을 임의 변경하지 않는다.
   force push·reset·clean·rebase·자동 병합은 하지 않는다. 오류가 나면 이유와 현재 보존 상태를 보고하고 멈춘다.
5. push 출력과 원격 main의 실제 커밋 ID를 조회해 로컬 HEAD와 비교한다.
   과거 origin/main 값이나 로컬 log만 보고 성공을 주장하지 않는다. 조회 실패나 불일치는 미확인/불일치로 보고한다.
6. 이번 커밋 안에 그 커밋 자신의 해시를 적으려고 하지 않는다. 실제 결과는 최종 보고에 남긴다.
7. 보고 후 종료한다. P1-2·추적 카메라·Vista·전투·집·저장·Meshy는 진행하지 않는다.
