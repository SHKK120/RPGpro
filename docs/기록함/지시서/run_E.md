# DOC-02 / E — 미정·후순위·첫 구현 준비 정리

대상: RPGpro
목적: 기존 `docs/기록함/지시서/instruction_02_reviewed.md`의 E만 수행한다.
이 파일은 새 게임 기획이나 새 운영 체계가 아니라, 기존 E의 실행 범위와 전달된 D 검토 결과를 정리한 지시다.

## 전달된 외부 검토 결과

ChatGPT가 사용자가 첨부한 D의 네 주제 문서와 최신 40·장부 본문을 검토했다.

- `30_데이터구조.md`, `33_지역.md`, `34_세이브.md`, `35_멀티경계.md`:
  `외부 본문 검토 적합 — 문서 이관`.
- 이 결과는 제안의 채택, 미정의 확정, 게임 기능·Save/Load·협동 동작의 통과를 뜻하지 않는다.
- ChatGPT가 실제 PC나 GitHub에 접속하여 확인했다는 의미가 아니다.
- 40의 문서 뼈대 항목에 남은 “이번 작업 시작 시 ... 미추적” 표현은 A 당시 이력과 D 현재 상태를 혼동할 수 있다. 아래 범위에서만 바로잡는다.
- D 작업을 재실행하거나 네 주제 문서를 다시 작성할 필요는 없다.

## 읽을 것

1. `AGENTS.md`, `docs/00_시작.md`, 최신 `docs/40_구현순서.md`, 장부의 필요한 최근 기록.
2. `docs/기록함/지시서/instruction_02_reviewed.md`의 공통 경계와 E·완료 보고 절.
3. E에서 질문을 모으는 데 필요한 B~D 주제 문서와 기존 50·60.
4. 환경 관련 질문을 정리할 때는 `docs/01_환경복구.md`의 실제 확인 사실을 참조한다.

실제 작업 경로와 시작 시 Git 상태를 먼저 확인한다. 기존 변경을 보존한다.
업로드 파일명의 `(1)`·`(2)`만 보고 로컬 파일을 개명하지 않는다.

## 변경 범위

이번에는 아래 네 문서만 수정한다.

- `docs/50_닫을것.md`
- `docs/60_나중에.md`
- `docs/40_구현순서.md`
- `docs/지시장부.md`

기존 E 지시가 이관 대상 문서의 읽기를 허용하는 것이지, A~D를 다시 수정하거나 구현을 시작하는 허가는 아니다.

## 수행 내용

### 1. docs/50_닫을것.md

기존 E의 규칙대로 B~D의 미정을 모은다.

각 항목:
질문 / 현재 제안 / 상태 / 안 정하면 막히는 조각 / 관련 정본 / 결정 기록.

- 실제 기존 번호를 확인하고 중복 없이 이어간다.
- 같은 질문은 한 항목으로 모으고 관련 정본을 참조한다.
- 첫 실행·시각 시험 전, 해당 기능 착수 전, 후속 단계의 질문을 구분한다.
- 모든 질문을 첫 실행의 선행 조건으로 만들지 않는다.
- 이미 01 등에 직접 확인된 환경 정보는 미확인으로 되돌리거나 다시 선택할 문제처럼 쓰지 않는다.
- 아직 모르는 렌더러·입력·시점·기타 규칙은 추측해 확정하지 않는다.
- 과거 추천안과 이번 검토에서 추가된 질문의 구분을 보존한다.
- 해결책이 없는 항목을 채우려고 새로운 디자인을 만들지 않는다.

### 2. docs/60_나중에.md

기존 E의 후순위 항목을 이름 / 지금 미루는 이유 / 다시 여는 조건으로 정리한다.

- 후순위 아이디어를 구현 명세나 제작 의무로 바꾸지 않는다.
- 현재 필요한 멀티의 구조 경계까지 후순위로 밀지 않는다.
- 개발자 진단과 플레이어용 Creative/Creator를 구분한다.
- 새로운 콘텐츠를 추가하거나 도구를 연결하지 않는다.

### 3. docs/40_구현순서.md

- D를 전달된 `외부 본문 검토 적합 — 문서 이관`으로 기록한다.
- E는 실제 작업에 따라 `작성완료·검토대기` 또는 부분 완료로 기록한다.
- A~C 보존과 D~E 미보존을 구별한다. 이번에 push하지 않은 내용을 보존 완료라고 쓰지 않는다.
- “문서 뼈대”의 현재 상태 설명에서 A 당시의 미추적 상태를 “이번 작업 시작 시”라고 쓰지 않는다.
  권장 표현:
  `문서 뼈대: AGENTS.md와 초기 docs 문서가 존재한다. 초기 생성·미추적 상태 이력은 지시장부의 001 — DOC-02 / A 참조.`
  실제 기록의 제목이 다르면 실제 위치를 참조한다.
- 기존 A 장부의 과거 이력을 삭제하거나 지금 상태로 소급 수정하지 않는다.
- P0~첫 완결 루프는 기존 E의 “초안 순서”로만 옮긴다. 구현 승인이나 단계별 상세 명세가 아니다.
- 다음 행동은 E 결과의 사용자 검토, 승인 범위의 D~E 보존, 첫 실행에 필요한 최소 결정 확인 후 P0 별도 지시다.
- P0나 Godot 프로젝트 생성으로 자동 진행하지 않는다.

### 4. docs/지시장부.md

실제 다음 번호로 이번 E 작업과 전달된 D 외부 검토 결과를 기록한다.
기존 여섯 항목 형식을 사용하고 검토 에이전트 0을 표시한다.
제안·미정·게임 검증 상태를 승격하지 않는다.
과거 005/D 기록을 새 결과로 덮어쓰지 않고 새 항목에서 후속 검토를 기록한다.
