## 4. 커밋·원격 보존

1. 위 8개 파일의 실제 diff와 내용을 확인한다.
   명백한 비밀값·읽기 오류·예상 밖 콘텐츠가 보이면 값을 재출력하지 말고 해당 문제를 보고한다.
2. 승인된 파일 경로만 명시적으로 stage한다. `git add .`, `git add -A`, `git add docs/`는 쓰지 않는다.
3. staged 목록이 승인 범위를 넘지 않는지 확인하고 문서 checkpoint 커밋을 만든다.
   메시지 예: `docs: checkpoint DOC-02 D-E and review follow-up`
4. 확인된 `origin/main`에 일반 push한다.
   force push, reset, clean, rebase, 자동 병합은 하지 않는다.
   작성자·인증·원격 이력 문제로 막히면 현재 보존 상태를 보고한다. 설정을 임의로 바꾸지 않는다.
5. push 출력과 **실제 원격 main 참조**를 조회하여 로컬 HEAD와 비교한다.
   로컬의 origin/main 추적 참조만 보고 실제 원격 조회를 했다고 쓰지 않는다.
   조회 불가나 불일치는 미확인으로 남기고 원격 성공을 추측하지 않는다.
6. 이미 같은 변경이 보존되어 있다면 불필요한 빈 커밋·반복 기록을 만들지 말고 실제 상태를 보고한다.
