# Codex 지시서 02 — 기획 이관 검토·수정본 v2.1

작성 기준일: 2026-09-06
대상: RPGpro — 성장·탐험·집 꾸미기 중심의 Godot 3D 프로젝트
성격: 한 번 사용하는 문서 정리 지시서. 게임 코드 구현 명세가 아니다.

> **처음 실행할 때는 A만 수행하고 보고 후 멈춘다.**
> B~E는 사용자가 해당 단계를 지정했을 때만 수행한다. 같은 세션에서도 별도 지시로 이어갈 수 있다.
> 기존 `instruction_02_design_transfer.md`를 이어서 실행하지 않는다. 이 수정본을 기준으로 한다.
> 기존 지시서가 이미 적용되어 있다면 되돌리지 말고, 실제 파일과 비교하여 부족한 부분만 보완한다.
> 현재 작업에서는 commit/push를 하지 않는다. 단, 원격 보존이 확인되지 않았다는 사실을 마지막에 반드시 알린다.

## 0. 출처와 적용 경계

이 파일은 이 대화의 RPG 기획, 업로드된 AGENTS.md와 docs 초안, 「작업방식_인수인계_2.md」를 대조하여 만든 수정 제안이다. 사용자가 이 파일의 실행을 지시하면 여기의 문서 정리 규칙을 적용한다. 실제 저장소 상태를 미리 확인한 파일은 아니다.

### 프로젝트를 섞지 않는다

- 이 프로젝트는 성장·탐험·파밍·집 꾸미기와 이사를 중심으로 한 RPG다. `RPGpro`는 작업 폴더명이며 정식 게임명은 미정이다.
- Iron & Trenches의 1880~1910년, 60분 경기, 국가 경제, RTS 보급선, Unity/DOTS 규칙을 이관하지 않는다.
- 별도 미로 굴착 디펜스의 코어 방어, 일꾼 규칙, 씬 통과 이력, 「프로토타입 아트 0」를 이관하지 않는다.
- 이전 프로젝트에서는 **작업 방식만** 가져온다. 당시 30분 세션이라는 제약도 이번 세션의 실제 시간으로 단정하지 않는다.
- 이 RPG에서는 만들고 싶은 경험과 완성의 성취를 중시한다. 시장성이나 난이도만으로 핵심 취향을 삭제하지 않는다. 현재 작업 크기는 작게 유지한다.

### 내용의 상태를 구분한다

문서에는 다음 상태를 구분하여 기록한다.

- **[요구·채택 방향]**: 사용자가 설명한 취향·경험과 대화에서 수용한 큰 방향. 기능 구현이나 세부 수치 확정을 뜻하지 않는다.
- **[제안]**: AI가 추천한 규칙·구성·예시. 조용히 확정으로 바꾸지 않는다.
- **[미정]**: 답이 필요하다. 현재 추천안이 있으면 그것도 함께 보존한다.
- **[확인 사실]**: 파일이나 실제 출력으로 확인한 환경·작업 결과. 사용자 보고와 직접 확인을 구분한다.

이관 시 실제 저장소에 이 파일보다 구체적인 사용자 승인 기록이 있으면 보존한다. 여기서 명시적으로 바꾸는 항목 외에는 「현재 지시 우선」을 이유로 새 기록을 지우지 않는다. 출처가 불명확한 충돌은 양쪽과 영향을 보고하고, 관련 없는 이관은 계속한다. 상위 도구 지침과 권한 제한은 바꾸지 않는다.

## 1. 실행 전 확인 — 읽기만

1. `AGENTS.md`, `docs/00_시작.md`를 읽는다. 있으면 `docs/40_구현순서.md`의 현재 상태와 `docs/지시장부.md`의 최근 기록도 읽는다.
2. 작업 폴더 절대 경로, 최상위 목록, `project.godot` 존재 여부를 확인한다.
3. Git이 있으면 저장소 최상위 경로, 현재 브랜치, 시작 시 변경 파일, remote 이름을 확인한다. 인증 정보가 포함된 URL이나 비밀은 출력하지 않는다.
4. 기존 문서에는 `C:\Users\CKIRUser\RPGpro`, `C:\godot`이 기록되어 있다. 이것은 확인 후보이지 현재 사실의 증명이 아니다. 경로가 다르면 알리고, 다른 프로젝트인지 불명확할 때만 쓰기 전에 확인을 받는다.
5. `project.godot`이나 Git 저장소가 없어도 사용자가 지정한 문서 작업 폴더임이 확인되면 문서 정리는 가능하다. 엔진 프로젝트 생성·git init·remote 등록은 하지 않는다.
6. `(1)`이 붙은 업로드 파일명만 보고 로컬 파일을 개명하지 않는다. 실제 파일과 라우터를 확인한다. 같은 제목의 후보가 여러 개면 임의 선택·덮어쓰기를 하지 않는다.

### 쓰기·검증 범위

- 기존 대상 파일을 먼저 읽고 필요한 절만 수정한다. 같은 내용을 다시 실행해도 중복 생성하지 않는다.
- 게임 코드·씬·리소스·에셋·`project.godot`·Git 설정·엔진 설정은 바꾸지 않는다.
- 새 도구 설치, 플러그인 연결, AI 에셋 생성, 계정 인증, 시스템 보안 변경은 하지 않는다.
- 기존 미커밋 변경을 삭제하거나 되돌리지 않는다. reset/clean/강제 push를 실행하지 않는다.
- 이번에는 검토 서브에이전트 0개. 자동 검사 프레임워크를 새로 만들지 않는다.
- 문서 파일·링크·중복·UTF-8 내용의 기본 확인만 한다. 파일에 이상이 보이면 사실을 보고하고 임의 복구하지 않는다.
- 일반 작업은 라우터의 문서와 필요한 의존 문서만 읽는다. 이번 파일은 아래 명시한 대상에 대한 일회성 이관 허용이다. 프로젝트 전체 문서를 항상 읽도록 바꾸지 않는다.

## A. 기록·복구·재개 방식 — 첫 실행 대상

### A-1. AGENTS.md

기존 간결한 형식과 의미를 유지하며 다음을 보완한다. 상세 기획은 넣지 않는다.

- 사용자의 현재 프로젝트 지시를 따른다. 미정 디자인을 임의 확정하지 않는다.
- 시작 시 `docs/00_시작.md`와 `docs/40_구현순서.md`의 현재 상태를 읽고 필요한 문서로 이동한다.
- 라우터는 우선 읽기 경로다. 실제 작업에 꼭 필요한 의존 문서는 이유를 밝히고 읽을 수 있으며, 반복적으로 필요하면 라우터를 보완한다.
- 저장소를 수정하는 구현 AI는 하나다. 외부 검토는 자료이지 자동 승인이나 구현 명령이 아니다.
- 한 번에 지시된 조각만 수행한다. 미정은 50, 후순위는 60에 기록한다.
- 끝에는 40의 재개 지점과 지시장부를 갱신한다. 기록함은 필요한 기록만 참조한다.
- 기술적 확인과 사람의 플레이·시각·재미 판정을 구분한다. 미실행을 통과로 적지 않는다.
- 문서 작업에 검토 에이전트나 새 테스트 체계를 만들지 않는다.
- commit/push는 해당 작업에 주어진 승인 범위만 따른다. 로컬 작성과 원격 보존을 구별한다.

이후 세션에서 이전 규칙을 따르는 징후가 보이면 현재 파일을 다시 읽도록 안내한다. 앱 전역 설정이나 홈 디렉터리 지침은 수정하지 않는다.

### A-2. docs/00_시작.md

기존 라우터를 유지하며 다음을 추가한다.

| 작업 | 읽을 곳 |
|---|---|
| 현재 조각·다음 행동·중단 지점 | 40_구현순서.md |
| 지시 이력·변경 이유 | 지시장부.md의 필요한 최근 항목 |
| 과거 지시·통과 근거 찾기 | 기록함/README.md 이후 필요한 파일만 |
| PC 복구·도구 경로·원격 보존 | 01_환경복구.md |

정본 소유를 분리한다.

- 01: 환경 경로·도구 버전·복구 절차.
- 10~15: 경험·플레이 규칙·시각 원칙.
- 30~35: 데이터·저장·권한의 의미와 경계. 실제 수치는 게임 데이터가 생긴 뒤 그쪽이 정본.
- 40: 현재 작업 상태와 다음 행동. 00에 같은 상태를 별도 복제하지 않는다.
- 50: 미정 질문, 제안, 결정 이력. 확정된 규칙 본문을 통째로 중복 보관하지 않는다.
- 60: 보류 아이디어와 여는 조건.
- 지시장부: 실제 지시와 실제 변경 이력.
- 기록함: 예전 지시·보고·이미지. 현재 규칙을 결정하는 자동 입력이 아니다.

### A-3. docs/01_환경복구.md

기존 「미정」을 확인 가능한 정보와 미확인 정보로 나눈다.

- 프로젝트 경로: 실제 읽기 결과가 있으면 기록.
- Git 저장소/브랜치/remote: 실제 결과를 기록. 없거나 접근할 수 없으면 그대로 표시.
- Godot: 현재 기록은 4 계열, 폴더 C:\godot. 정확한 실행 파일명과 버전은 설치 폴더 등 허용된 범위에서 확인할 수 있을 때만 기록한다. 확인을 위해 설치하거나 권한을 바꾸지 않는다.
- 렌더러: project.godot 등에서 확인되면 기록. 없으면 「P0 전에 확인」. Forward+/Mobile/Compatibility 중 하나를 추측하여 선택하지 않는다.
- Codex: 사용자 보고로 Beta에서 접속·문서 작업을 진행한 상태다. 정확한 제품명·빌드·선택 방법이 확인되지 않으면 미확인으로 둔다. 초기화 후 재현을 보장한다고 쓰지 않는다.
- 한 세션 가용 시간: 이번 프로젝트에서 확인되지 않았으면 미정. 기존 게임의 30분을 그대로 확정하지 않는다.

복구/종료 절차는 원칙과 실제 확인된 경로만 쓴다.

시작: 허용된 도구 준비 → 원격 정본 복원 → 실제 작업 경로 확인 → 00과 40 읽기 → 지정 조각 시작.
기존 작업 폴더가 있을 때 무조건 pull·reset하지 않는다. 미커밋 변경부터 확인한다.
종료: 결과 확인 → 허용된 범위 커밋·push → 원격 반영 확인 → 미보존 항목 알림.

주의:
- 로컬 git log만으로 GitHub 업로드 성공을 선언하지 않는다. 별도 승인으로 push한 뒤 원격 브랜치 커밋을 확인하거나 GitHub에서 확인한다.
- 나중에 생길 게임 플레이 세이브는 프로젝트 소스와 별개다. Godot의 user:// 데이터는 일반적으로 프로젝트 폴더 밖에 있다. GitHub에 코드를 올렸다고 플레이 세이브가 자동 보존되는 것으로 취급하지 않는다. 실제 경로·개인 데이터 백업은 세이브 조각에서 정한다.
- 인증 토큰, API 키, 계정 캐시, Codex 인증 파일은 저장소·장부·스크린샷에 넣지 않는다.
- 지금은 복구 문서만 보완한다. 실제 clone/push/백업 자동화는 실행하지 않는다.

### A-4. 기록함과 지시장부

`docs/기록함/README.md`를 실제 파일로 만든다. 이미 있으면 필요한 부분만 보완한다.

내용:
- 목적: 예전 지시서, 작업 결과, 실제 통과 근거를 보관하는 곳.
- 현재 정본 아님. 오래된 지시를 자동 재실행하지 않는다.
- 보관 분류 예: 지시서 / 작업결과 / 통과샷. 실제 내용이 생길 때 하위 폴더를 추가한다.
- 통과샷은 실제 플레이 확인 자료만. 이미지나 플레이 결과를 만들어내지 않는다.
- 큰 영상·제작 원본은 승인된 외부 보관소에 두고 식별 정보만 연결한다. 지금 업로드하지 않는다.

이 수정본을 `docs/기록함/지시서/instruction_02_reviewed.md`에 보관한다. 원본 내용을 보존하며, 이미 같은 내용이 있으면 중복 생성하지 않는다. 같은 경로에 다른 버전이 있으면 덮어쓰지 말고 버전 구분이 필요하다고 보고한다. 보관본이 B~E 자동 실행을 허가하는 것은 아니다.

지시장부에는 문서 이름만 있는 상태를 실제 기록으로 바꾼다. 과거 작업을 수행한 것처럼 소급 기입하지 않는다. 번호가 있다면 실제 다음 번호를 확인하여 사용한다.

각 단계 기록은 다음 여섯 항목으로 한다.

    ▶ 지시       실제 받은 지시 또는 전달 지시 요약(요약이면 표시)
    자리         손댄 파일·절과 이유
    한 일        실제 변경 내용 · 검토 에이전트 0
    바뀐 정본    변경된 규칙/정보와 그 정본 위치 · 없으면 없음
    반경         실제 변경 파일 수 · 이전 확인 영역에 미친 영향
    확인법       직접 확인한 사실 / 사람이 볼 것 / 미확인을 구분

## 4. 보존 승인 — 지금 실행하지 않는 별도 절차

사용자가 검토 후 명시적으로 이번 문서의 commit/push를 지시했을 때만:
- 실제 저장소·브랜치·remote를 확인하고 이번에 검토된 문서만 선택한다.
- 인증 정보, 대형 원본, 게임 플레이 개인 세이브를 무심코 포함하지 않는다.
- unrelated 변경과 이미 staged 된 내용도 확인한다. 임의로 사용자 작업을 취소하지 않는다.
- push 성공을 확인하고 로컬 HEAD와 대상 원격 브랜치 커밋을 대조하거나 GitHub에서 확인한다. 차이가 나면 이유를 확인하되 force push하지 않는다.
- 끝에는 로컬 커밋과 원격 보존 여부를 보고한다. 원격 확인 불가를 성공으로 쓰지 않는다.

이 파일을 읽는 것만으로 위 보존 절차의 실행을 승인받은 것이 아니다.
