# P1-1 — 최소 이동 시험안

대상: RPGpro
목적: P0에서 확인한 화면을 바탕으로 캡슐을 직접 움직이고, 바닥·상자와의 기본 충돌을 확인한다.

> 이 파일은 **새로 제안하는 P1-1 한정 시험안**이다.
> 사용자가 `start_P1_1.md를 읽고 P1-1 시험안으로 구현해. commit/push는 하지 마.`라고 지시했을 때만 구현한다.
> 검토만 요청받으면 파일을 수정하지 않는다.
> 이 파일을 읽는 것만으로 P1 전체, 최종 조작·아트, commit/push를 승인받은 것은 아니다.

## 1. 이번에 시험할 것

| 항목 | P1-1 한정 선택 |
|---|---|
| 조작 대상 | 노란 캡슐 하나. 최종 캐릭터 모델이 아니다 |
| 이동 | WASD, 카메라의 수평 방향 기준으로 전후좌우 |
| 입력 감각 | 누르면 이동하고 떼면 수평 이동을 멈춤. 관성·달리기 없음 |
| 대각선 | 허용하되 직선보다 월드 기준 속도가 커지지 않음 |
| 카메라 | P0의 높은 사선 원근 시점을 유지. 추적·회전·줌 없음 |
| 충돌 | 바닥·상자 두 개·시험장 경계와 충돌. 상자는 밀리지 않음 |
| 시험장 | 기존 바닥 바깥으로 떨어지지 않도록 눈에 보이는 낮은 막이를 둠 |
| 재실행 | 시험 시작 위치에서 다시 시작. 위치 저장이나 부활 기능은 아님 |
| 유지 | 기존 Compatibility와 창 크기, 조명·기본 재질 |
| 제외 | 점프, 회피, 공격, 채집, 집, 저장, Vista, 새 에셋 |

시험장 경계는 이번 이동 테스트의 설비다.
최종 월드의 경계, 절벽 낙하, 생존·사망 규칙을 확정하는 것이 아니다.
캡슐의 조작 실험은 최종 3D 캐릭터나 WASD 조작을 영구 채택했다는 뜻이 아니다.

## 4. 최소 구현

### 4-1. 입력과 이동 스크립트

새 스크립트: `scripts/prototype/p1_player.gd`

- GDScript로 `CharacterBody3D`의 최소 이동만 구현한다.
- 주 동작은 `_physics_process(delta)`에서 입력 → 수평 velocity → 중력 → `move_and_slide()`로 처리한다.
- 매 프레임 position을 직접 더하거나, 장애물을 지난 뒤 좌표를 되돌리는 방식으로 충돌을 대신하지 않는다.
- 이동속도는 이 시험 스크립트의 export 값 하나로 소유한다.
  초기 시험값은 4.0 월드 단위/초. 최종 밸런스가 아니다.
  별도 데이터 리소스·속도 설정 관리자·범용 이동 프레임워크를 만들지 않는다.
- 카메라 참조를 명시적으로 연결하고, 실제 연결과 노드 타입을 확인한다.
  필수 연결이 없으면 명확한 초기 오류를 남기고 수평 이동을 중지한다.
  매 프레임 같은 오류를 반복 출력하지 않는다.

`project.godot`에는 필요한 네 액션만 추가한다:
- `move_left` : 물리 키 A
- `move_right` : 물리 키 D
- `move_forward` : 물리 키 W
- `move_back` : 물리 키 S

동일 액션이 있으면 먼저 확인하고 중복 등록하거나 기존 매핑을 무심코 지우지 않는다.
스크립트는 액션 이름으로 읽는다. UI용 `ui_*` 액션을 이동에 재사용하거나 키 코드를 코드에 박지 않는다.
화살표·점프·달리기·회피·마우스 이동·키 재설정 UI는 추가하지 않는다.
한글 IME의 문자 입력과 구분되게 physical key 방식으로 시험한다.

이동 방향:
1. `Input.get_vector("move_left", "move_right", "move_forward", "move_back")`로 2D 입력을 얻는다.
2. 실제 카메라의 오른쪽(+X)과 전방(-Z)을 수평 XZ면으로 투영한 단위 방향을 사용한다.
3. W가 전방이 되도록 입력 Y의 부호를 적용한다. 카메라의 아래쪽 기울기로 캡슐이 지면을 파고들게 하지 않는다.
4. 변환된 수평 방향의 길이를 최대 1로 제한하여 대각선의 속도 증가를 막는다.
5. 입력이 없으면 수평 velocity만 0으로 한다. 바닥 접촉을 위한 수직 처리와 구분한다.
6. `move_and_slide()`에 사용하는 velocity에 delta를 다시 곱하지 않는다.
   중력 같은 가속도를 속도에 누적할 때는 delta를 사용한다.

현재 엔진의 지원 API를 확인해 중력을 처리한다.
별도 점프·중력 설정 체계를 추가하지 않고 기존 엔진/프로젝트 값을 우선한다.
애니메이션, 방향 전환 모델, 장비, 체력, 네트워크 추상화는 없다.

### 4-2. 충돌과 시험장

- 캡슐은 CharacterBody3D + CapsuleShape3D의 CollisionShape3D + 보이는 캡슐 메시로 구성한다.
- 바닥·상자 두 개는 StaticBody3D + 단순 BoxShape3D 충돌 형태를 사용한다.
- 메시와 충돌체의 실제 크기·변환을 맞춘다. 물리 노드의 비균등 스케일로 억지 조정하지 않는다.
- 캡슐 시작 위치는 바닥 위의 빈자리다. 바닥·상자·경계와 겹쳐 시작하지 않는다.
- 상자는 고정 장애물이다. RigidBody나 밀기 기능을 추가하지 않는다.
- 기본 충돌 설정을 단순하게 맞추고, 서로 탐지하지 못하는 mask/layer 조합을 피한다.

바닥 외곽 네 방향에 보이는 단순한 막이와 대응하는 충돌을 추가한다.
카메라에 시험 영역이 보이도록 하고, 경계의 높이·두께는 캡슐이 쉽게 넘어가거나 틈으로 빠지지 않도록 실제 크기에 맞춘다.
경계는 플레이 영역 안쪽 가장자리에 둬서 바닥 밖에 닿기 전에 막히게 한다.
보이지 않는 거대 충돌체나 좌표 clamp로 가장자리 문제를 숨기지 않는다.
추락 리셋·사망·귀환·월드 경계 시스템으로 범위를 넓히지 않는다.

카메라 위치·각도·FOV는 P0의 기존 값을 유지한다.
넓은 맵·추적 카메라를 추가하지 않고 기존 화면 안에서 시험한다.
렌더러, 창 크기, 기존 조명·재질은 바꾸지 않는다.

## 5. 구현 전에 사람 확인 목록

`docs/42_P1_1_최소이동.md`를 한 장으로 만든다.
파일이 이미 다른 용도로 쓰이면 덮어쓰지 말고 번호 충돌을 보고한다.
목표, 시험 선택, 입력, 여는 방법, 아래 목록, 실제 기술 결과만 적는다.
실제 수치의 정본은 스크립트/씬/프로젝트 설정이고 문서는 그 위치와 의도를 기록한다.
사람 확인은 모두 미확인으로 시작한다.

| 항목 | 되는 경우 | 안 되어야 하는 경우 |
|---|---|---|
| 1. 시작 | F5로 바닥·캡슐·상자·경계가 보이고 캡슐이 바닥에 선다 | 시작부터 끼거나 지면을 뚫고 떨어진다 |
| 2. 네 방향 | 실행 화면에 입력 포커스를 둔 뒤 WASD 방향이 카메라 기준으로 이해된다 | 방향이 뒤집히거나 한 축만 움직인다 |
| 3. 대각·정지 | 대각 이동이 가능하고 손을 떼면 수평 이동이 멈춘다 | 대각 입력만으로 불필요한 가속이 생기거나 계속 미끄러진다 |
| 4. 상자 충돌 | 상자를 향하면 막히고, 옆으로 움직여 돌아갈 수 있다 | 상자를 관통·밀거나 접촉 후 빠져나올 수 없다 |
| 5. 경계 | 네 외곽과 모서리에서 막히고 다시 안쪽으로 이동할 수 있다 | 바닥 밖으로 빠지거나 모서리에 영구적으로 낀다 |
| 6. 카메라·비목표 | 캡슐이 움직여도 카메라는 고정이고 점프·공격은 없다 | 추적·줌·미승인 기능이 추가된다 |
| 7. 재실행 | F8 종료 후 다시 F5로 시작하면 초기 위치에서 정상 조작된다 | 참조 오류가 나거나 이전 실행의 입력이 남는다 |
| 8. P0 보존 | P0 씬을 열고 F6로 실행하면 원래 정적 화면을 볼 수 있다 | 원본 씬이 바뀌거나 오류가 생긴다 |

원근 시점에서 화면 픽셀 이동거리만 비교해 월드 속도를 정확히 측정했다고 쓰지 않는다.
대각선 길이 제한·delta 처리 같은 코드 확인과 사람이 느끼는 조작감은 구별한다.
F5 실행 뒤 입력이 없으면 먼저 게임 화면의 입력 포커스를 확인한다.
포커스 문제 때문에 키 매핑·시스템 정책을 임의 변경하지 않는다.

## 7. 기술 확인과 사람 확인을 분리

기존 허용 환경에서 현재 Godot 실행 파일의 --help와 실제 API를 기준으로 확인한다.

- 파싱·import, 메인 씬의 짧은 로드 확인.
- 일반 그래픽 실행으로 프레임을 표시할 수 있는지 확인.
- 실제 입력·충돌을 직접 확인하지 못했으면 코드 검토/로드 성공과 구분해 미확인으로 보고.
- 가능하면 P0 원본이 변경되지 않았다는 diff와 기존 씬의 로드를 확인.
- 새 자동 테스트 프레임워크, 별도 테스트 씬, 다수 검토 에이전트는 만들지 않는다.
- headless Movie Maker나 영상 출력 재시도는 하지 않는다.
- 이전 드라이버 경고와 새로운 스크립트·씬 오류를 구분한다.
- 오류가 나면 이번 파일 범위에서 수정하되 설치·보안 우회·엔진/드라이버 변경은 하지 않는다.
- 사람이 직접 이동·충돌을 보지 않았다면 사람 확인 통과로 쓰지 않는다.
- 성능 벤치마크, 최종 아트·게임 재미는 이번 통과 범위가 아니다.

## 8. 보고 후 중단

보고:
1. 실제 루트/엔진, 시작 시 Git 상태.
2. 변경·생성한 파일, 엔진 자동 생성 파일, 보존한 기존 변경.
3. 이번 시험 선택과 최종 미정의 구분.
4. 실제 실행·오류·검증 결과와 미확인 항목.
5. 사람이 F5에서 볼 것과 입력·충돌 확인 항목.
6. P0 원본 보존 여부, 40의 상태, 장부 번호.
7. staged/수정/삭제/미추적 상태와 이번 변경 원격 미보존.

commit/push·stage는 하지 않는다.
P1-2, 추적 카메라, Vista, 바다, 전투, 집, 저장, Meshy 연결로 자동 진행하지 않는다.
사용자에게 파일 직접 편집이나 노드 수동 배치를 요구하지 않는다.
