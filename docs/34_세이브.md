# 세이브

## 문서의 역할

저장하고 복구해야 하는 상태와 Save/Load 정책을 정의한다.

## 이 문서가 소유하는 정보

- 저장 대상과 제외 대상
- Save/Load 데이터의 경계
- 버전 및 마이그레이션 원칙

## 이 문서가 소유하지 않는 정보

- 멀티플레이 권한 구조
- 개별 콘텐츠 값
- 저장 기능 구현 코드

## [요구·채택 방향]

- 이사와 재접속 뒤에도 꾸민 집과 수집·성장 상태를 유지할 수 있어야 한다.
- 이번 문서 단계에서 세이브를 구현하지 않는다는 뜻은 초본에서 저장을 제외한다는 뜻이 아니다.

## [제안]

- 가구 배치와 회수를 만든 초기 단계에 최소 저장/로드 검증을 붙인다. 많은 가구를 만든 뒤로 미루지 않는다.
- Profile, Player, World, House, Region은 책임 구분 후보다. 다섯 개 파일로 저장하라는 뜻이 아니다.
- 집에 딸린 배치는 집 기준 로컬 변환과 개별 상태를 고려한다. Local Position만으로 저장 정책이 완성됐다고 보지 않는다.
- 버전, 콘텐츠 ID 변경, 누락된 에셋, 중단된 저장의 복구 방침을 별도로 결정한다.
- 코드·문서의 원격 보존과 플레이 세이브 백업을 구분한다. 실제 `user://` 경로는 환경에서 확인한다.

## [미정] 과거 추천안도 보존

- 월드 귀속 캐릭터를 기본으로 삼는 방안은 제안이 있었지만 사용자 확정으로 올리지 않는다.
- 다른 월드의 캐릭터 반입
- Profile의 외형과 도감 범위
- 공동 집과 개인 집의 경계

이 항목들은 저장 조각 전에 필요한 부분만 결정한다.

## [M04 시험 선택]

기존 `green_coast_m02/save_v1.json` 형식과 검증 후 교체·이전 정상본 정책을 유지하면서 다음 World 진행 선택 키를 더한다.

- `boss_defeated`
- `boss_reward_claimed`
- `boss_trophy_owned`
- `boss_trophy_displayed`
- `boss_growth_core_owned`
- `green_coast_first_loop_completed`

키가 없는 M02/M03 저장은 모두 `false` 기본값으로 읽는다. Boss 현재 HP·Phase·공격·Projectile·Arena 전투 중 상태는 저장하지 않는다. 격파와 보상 수령을 분리해 격파 직후 종료하더라도 미수령 보상을 복원하며, +2·전시·완료 상태의 모순은 저장 검증에서 거부한다. 이는 M04 시험 구현이며 정식 Save Architecture나 마이그레이션 정책을 닫지 않는다.

## [MACRO-01 시험 구현]

기존 파일과 교체·이전 정상본 정책을 유지하며 `current_region_id`, Region 2 해금·발견, Ore 수량·고정 Pickup ID, 두 번째 집터, Home Storage, 테마, 제작 결과와 골격 완료 상태를 선택 키로 추가한다. 키가 없는 기존 저장은 Green Coast와 빈 Home/Region 2 상태로 읽으며 기존 저장을 삭제하거나 자동 초기화하지 않는다.
