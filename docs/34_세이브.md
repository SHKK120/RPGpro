# 세이브

## 문서의 역할

저장하고 복구해야 하는 상태와 Save/Load 정책을 정의한다.

## 이 문서가 소유하는 정보

- 저장 대상과 제외 대상
- Save/Load 데이터의 경계
- 버전 및 마이그레이션 원칙

## 이 문서가 소유하지 않는 정보

- 멀티플레이 권한 구조
- 개별 콘텐츠 값
- 저장 기능 구현 코드

## [요구·채택 방향]

- 이사와 재접속 뒤에도 꾸민 집과 수집·성장 상태를 유지할 수 있어야 한다.
- 이번 문서 단계에서 세이브를 구현하지 않는다는 뜻은 초본에서 저장을 제외한다는 뜻이 아니다.

## [제안]

- 가구 배치와 회수를 만든 초기 단계에 최소 저장/로드 검증을 붙인다. 많은 가구를 만든 뒤로 미루지 않는다.
- Profile, Player, World, House, Region은 책임 구분 후보다. 다섯 개 파일로 저장하라는 뜻이 아니다.
- 집에 딸린 배치는 집 기준 로컬 변환과 개별 상태를 고려한다. Local Position만으로 저장 정책이 완성됐다고 보지 않는다.
- 버전, 콘텐츠 ID 변경, 누락된 에셋, 중단된 저장의 복구 방침을 별도로 결정한다.
- 코드·문서의 원격 보존과 플레이 세이브 백업을 구분한다. 실제 `user://` 경로는 환경에서 확인한다.

## [미정] 과거 추천안도 보존

- 월드 귀속 캐릭터를 기본으로 삼는 방안은 제안이 있었지만 사용자 확정으로 올리지 않는다.
- 다른 월드의 캐릭터 반입
- Profile의 외형과 도감 범위
- 공동 집과 개인 집의 경계

이 항목들은 저장 조각 전에 필요한 부분만 결정한다.
