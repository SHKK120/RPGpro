## 복구 및 종료 절차

### 시작

1. 허용된 도구를 준비한다.
2. 새 PC라면 `git clone https://github.com/SHKK120/RPGpro.git` 후 `main` 브랜치를 연다. 기존 작업 폴더가 있으면 무조건 pull·reset하지 않고 미커밋 변경부터 확인한다.
3. 실제 작업 경로를 확인한다.
4. `00_시작.md`와 `40_구현순서.md`를 읽는다.
5. 지정된 조각을 시작한다.

### 시각 작업 환경 복구

1. 위 Godot, Blender, uv/uvx와 MCP용 Python 경로가 실제로 존재하고 각 버전이 맞는지 확인한다.
2. `.codex/config.toml`에서 `rpgpro_blender_b1`의 절대 경로, `127.0.0.1:9876`, safe mode, telemetry 차단, 승인 모드와 관찰 도구 목록을 확인한다. 홈 `~/.codex/config.toml`로 옮기지 않는다.
3. Blender를 위 Portable 실행 파일로 열고 사용할 승인 `.blend`를 연다. 다른 열린 파일의 미저장 작업을 닫거나 덮어쓰지 않는다.
4. Blender 3D View의 N 사이드바에서 MCP for Blender 패널을 열고 애드온 서버를 시작한다. 외부 에셋·생성 서비스 체크박스와 API 키는 켜지 않는다.
5. Codex에서 새 작업을 열거나 MCP를 재시작해 프로젝트 설정을 다시 읽는다. 설치·애드온 복사를 먼저 반복하지 않는다.
6. `get_scene_info`를 호출해 열린 파일과 객체를 확인하고, 필요한 경우 `get_object_info`와 `get_viewport_screenshot`으로 관찰한다.
7. 연결 실패 시 Blender 앱, 애드온 활성화와 `127.0.0.1:9876` 리스닝을 먼저 확인한다. 방화벽 개방, 외부 바인딩, PATH·레지스트리 변경, safe mode 해제나 새 MCP 중복 등록으로 우회하지 않는다.
8. M05 등 시각 조각은 범위 문서와 선행 상태가 승인된 뒤 `$rpgpro-visual-slice`를 사용해 시작한다.

## 주의

- 로컬 `git log`만으로 GitHub 업로드 성공을 선언하지 않는다. 별도 승인으로 push한 뒤 원격 브랜치 커밋을 확인하거나 GitHub에서 확인한다.
- 게임 플레이 세이브는 프로젝트 소스와 별개다. Godot의 `user://` 데이터는 일반적으로 프로젝트 폴더 밖에 있으며, 실제 경로와 개인 데이터 백업은 세이브 조각에서 정한다.
- GitHub에 코드를 올렸다고 플레이 세이브가 자동 보존되는 것으로 취급하지 않는다.
- 인증 토큰, API 키, 계정 캐시, Codex 인증 파일은 저장소, 장부, 스크린샷에 넣지 않는다.
- `.agents/skills/rpgpro-visual-slice/`는 프로젝트 재현 규칙이므로 정본 체크포인트에 포함한다. `.codex/config.toml`은 로컬 경로와 MCP 설정을 담은 PC별 파일이므로 Git에서 제외하고 위 절차에 따라 재설정한다.
- Git 체크포인트는 게임 코드와 프로젝트 문서를 보존하지만 Godot `user://` 개인 Save, 외부 Blender 원본, 도구 설치 파일과 계정·인증 설정은 보존하지 않는다.
