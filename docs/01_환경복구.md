# 환경 복구

## 문서의 역할

프로젝트를 시작하거나 개발 환경을 복구할 때 필요한 절차를 관리한다.

## 이 문서가 소유하는 정보

- 필수 도구와 버전 요구 사항
- 프로젝트 실행 및 복구 절차
- 환경 복구 후 기계적으로 확인할 항목

## 이 문서가 소유하지 않는 정보

- 게임 플레이 규칙
- 콘텐츠와 수치
- 기능별 구현 순서

## 복구 및 종료 절차

### 시작

1. 허용된 도구를 준비한다.
2. 원격 정본을 복원한다. 기존 작업 폴더가 있으면 무조건 pull·reset하지 않고 미커밋 변경부터 확인한다.
3. 실제 작업 경로를 확인한다.
4. `00_시작.md`와 `40_구현순서.md`를 읽는다.
5. 지정된 조각을 시작한다.

### P0 프로젝트 열기

- Godot 프로젝트 관리자에서 `C:\Users\CKIRUser\RPGpro\project.godot`를 가져와 연다.
- 또는 `C:\godot\godot.exe --editor --path C:\Users\CKIRUser\RPGpro`로 연다.
- 현재 F5 메인 씬은 `project.godot`의 `run/main_scene`을 따른다. P0 비교 원본은 `res://scenes/prototype/p0_bootstrap.tscn`이다.
- CLI import·headless 실행 결과와 사람의 실제 화면 확인 결과는 구분해 기록한다.

### 종료

1. 결과를 확인한다.
2. 승인된 범위에서만 commit·push한다.
3. 원격 반영을 확인한다.
4. 원격에 보존되지 않은 항목을 알린다.

## 주의

- 로컬 `git log`만으로 GitHub 업로드 성공을 선언하지 않는다. 별도 승인으로 push한 뒤 원격 브랜치 커밋을 확인하거나 GitHub에서 확인한다.
- 게임 플레이 세이브는 프로젝트 소스와 별개다. Godot의 `user://` 데이터는 일반적으로 프로젝트 폴더 밖에 있으며, 실제 경로와 개인 데이터 백업은 세이브 조각에서 정한다.
- GitHub에 코드를 올렸다고 플레이 세이브가 자동 보존되는 것으로 취급하지 않는다.
- 인증 토큰, API 키, 계정 캐시, Codex 인증 파일은 저장소, 장부, 스크린샷에 넣지 않는다.
- 현재는 복구 문서만 보완한다. 실제 clone, push, 백업 자동화는 실행하지 않는다.
