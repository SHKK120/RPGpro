# 데이터 구조

## 문서의 역할

게임 데이터가 공유하는 구조와 참조 원칙을 정의한다.

## 이 문서가 소유하는 정보

- 데이터 종류별 책임과 경계
- ID와 참조에 관한 공통 원칙
- 데이터 간 의존 관계

## 이 문서가 소유하지 않는 정보

- 실제 콘텐츠 값
- 저장 파일 형식과 마이그레이션 정책
- 게임 시스템 구현 코드

## [제안] 원칙

- 콘텐츠 정의와 플레이 중 상태를 분리한다. 아이템 종류의 정의와 실제 아이템 한 개의 상태는 다르다.
- 정의 ID, 배치된 객체 ID, 지역 ID, 집터 ID를 구분하는 구조를 고려한다.
- 저장에는 장면 트리의 순간적인 노드 위치나 UI 이름에만 의존하지 않는 식별 방법이 필요하다.
- 데이터 형태가 달라져도 기존 콘텐츠의 의미가 무심코 바뀌지 않도록 버전과 변환 경계를 둔다.
- 플레이어의 요청과 실제 상태 변경 책임을 분리하되, 초본부터 거대한 범용 프레임워크를 만들지는 않는다.

## [제안] 후보 명칭

`ItemData`, `EnemyData`, `FurnitureData`, `ThemeData`, `RegionData` 등은 후보 명칭이다. 클래스, 상속 구조, 파일 수를 확정하거나 구현하지 않는다.
