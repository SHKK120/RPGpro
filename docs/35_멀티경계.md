# 멀티 경계

## 문서의 역할

현재 싱글플레이 구현이 미래 협동 플레이를 막지 않도록 구조적 경계를 정의한다.

## 이 문서가 소유하는 정보

- 멀티플레이의 미래 목표
- World 상태와 Player 상태의 구조적 경계
- 향후 권한 및 저장 구조에 필요한 제약

## 이 문서가 소유하지 않는 정보

- 현재 단계의 네트워크 구현
- Steam 연동 구현
- 게임 플레이의 세부 규칙

## [요구·채택 방향] 현재 범위

### 현재

- 싱글플레이 우선

### 향후 목표

- 2~4인 Steam 친구 초대형 협동
- Host-authoritative
- Dedicated Server 운영 없음

### 현재 코드 구조에서 지킬 경계

- World 상태와 Player 상태를 분리한다.
- 월드 객체는 고유 ID를 가질 수 있도록 설계한다.
- Player가 World 상태를 무제한 직접 수정하는 구조를 피한다.
- 저장 구조가 특정 플레이어 하나에만 종속되지 않게 한다.

현재 단계에서는 네트워크 코드를 구현하지 않는다.

## 구조적 한계

설계 경계를 남긴다고 향후 멀티플레이 추가가 무수정으로 가능해지는 것은 아니다.

## [미정] 향후 협동 검증 항목

- 호스트 종료 처리
- 서로 다른 지역에 있는 플레이어 상태
- 동시 채집
- 창고의 중복 획득 방지
- 가구 동시 편집
- 집 이전 권한

## [제안] 협동 구현을 시작할 때

- 실제 협동 구현 단계가 열리면 작은 동시 상호작용 시험부터 한다.
- 현재는 네트워크 추상화 체계를 만들지 않는다.

## [제안] 디버그 구분

- 개발자 진단: 필요한 버그 조각에서 범위를 지정하여 사용한다.
- 호스트 관리: 실제 권한과 영향을 별도로 검토한다.
- 플레이어 Creative/Creator: 후순위로 둔다.

`return_home` 같은 명령이 일반 플레이 규칙을 바꾸는지 검토하지 않은 채 무해한 관리 명령으로 확정하지 않는다.
