# Blender-3 + Godot-1 바위 반입

## 목표

Blender B2의 단일 바위를 GLB로 내보내고, 기존 P1 이동 시험을 바꾸지 않는 별도 Godot 장면에서 가져오기·표시·접지 여부를 확인한다. 이번 결과는 반입 기술과 시각 확인을 위한 시험이며 최종 아트나 정식 에셋 파이프라인 확정이 아니다.

## 입력과 산출물

- Blender 입력: `C:\Users\CKIRUser\BlenderTrials\B2\b2_rock_01.blend`
- Blender 출력: `C:\Users\CKIRUser\BlenderTrials\B3\b2_rock_01.glb`
- Godot 반입: `res://assets/prototype/blender/rocks/b2_rock_01.glb`
- Godot 시험 장면: `res://scenes/prototype/p2_rock_import_test.tscn`

## 적용 내용

- B2 저장본을 Blender 4.5.13 LTS로 다시 열어 `B2_Rock_01` 한 개와 메시·재질 통계를 확인했다.
- 현재 저장본의 위치·회전이 앞선 B2 보고와 달라져 있었다. 원본 `.blend`를 저장하거나 수정하지 않고 내보내기 메모리 사본에서만 위치·회전을 0으로 복구했다.
- 단일 바위만 표준 glTF 2.0 GLB로 내보냈다. 모델 메시와 재질 자체는 다시 다듬지 않았다.
- P1 원형을 건드리지 않고 환경, 녹색 바닥, 방향광, 고정 게임 성격 카메라, GLB 인스턴스 한 개만 가진 별도 장면을 만들었다.
- `project.godot`, P1 이동·카메라·우클릭 코드, NavMesh는 수정하지 않았다.

## 기술 확인 결과

- Blender 출력: 크기 `(1.5, 1.2, 0.9)`, 정점 25, 폴리곤 41, 삼각형 46, 재질 1개, non-manifold 에지 0.
- GLB 구조: glTF 2.0, 장면·노드·메시·primitive·재질 각 1개.
- BlenderTrials 원본 GLB와 프로젝트 반입본의 SHA256 일치.
- Godot GLB import 성공, `.import` 메타와 imported scene 생성 확인.
- 시험 장면 헤드리스 로드 및 에디터 재열기 확인에서 오류 없음.
- 일반 Compatibility 그래픽 실행 성공. 1280×720 프레임에서 바위, 바닥, 그림자가 표시됐다.
- Godot 반입 메시: surface 1개, 삼각형 46개, 재질 `B2_Rock_Gray`, Roughness 약 `0.9`, Metallic `0.0`.
- Godot 월드 AABB 위치 `(-0.78, 0.0, -0.6)`, 크기 `(1.5, 0.9, 1.2)`로 바닥 Y=0에 접한다.
- 명백한 누락, 공중 부양, 바닥 관통, 재질 파손은 기술 화면 확인에서 관찰되지 않았다.
- 기존 Intel HD Graphics 530 OpenGL 3.3 품질 경고와 Compatibility의 ANGLE 전환은 유지됐다.

## 사람 확인 항목

- 실제 화면에서 바위 형태와 실루엣이 바위로 읽히는가
- 게임 카메라에서 크기감과 방향이 적절한가
- 바닥에 자연스럽게 놓여 보이는가
- 회색 재질과 조명 결과가 수용 가능한가
- 종료 후 재실행해도 동일하게 표시되는가

## 아직 미검증인 것

- 최종 아트 적합성과 최종 에셋 파이프라인
- 실제 게임 플레이에서의 크기 감각
- 성능
- 충돌, 상호작용, 채집
- 정식 게임 월드 배치
- 바위 변형 2~3종과 해안·Vista 구현

위 반입 단계의 상태는 `Blender-3 + Godot-1 — 구현완료·사람확인대기`였다. 아래 M01에서 같은 GLB와 시험 결과를 재사용한다.

## M01 목표와 범위

완료된 바위 반입을 다시 만들지 않고, 기존 P1 이동·우클릭·추적 카메라를 재사용해 작은 단층 해안 산책로와 전망 진입·복귀까지 한 장면으로 연결한다. 아래 해안과 바다는 시각 배경이며 실제 경사 이동, 다층 내비게이션, 수영, 낙하·부활, 최종 Vista 규칙은 포함하지 않는다.

- 실행 장면: `res://scenes/prototype/coast_preview.tscn`
- 전용 NavMesh: `res://scenes/prototype/m01_navigation_mesh.tres`
- 전망 제어: `res://scripts/prototype/m01_coast_preview.gd`
- NavMesh 재현 도구: `res://tools/m01_bake_navigation.gd`
- 재사용 바위: `res://assets/prototype/blender/rocks/b2_rock_01.glb`

## M01 구현 결과

- 시작점에서 노란 전망 표식까지 이어지는 단층 산책로, 보이는 목책·절벽과 일치하는 충돌 경계, 길가 바위 두 개를 배치했다.
- 아래쪽 모래 해안과 충돌 없는 바다를 시각 배경으로 두고, 시간 기반 정점 변형만 사용하는 가벼운 바다 셰이더를 적용했다.
- 같은 GLB의 원경 바위 두 개를 섬 실루엣으로 재사용했다. 총 바위 인스턴스는 네 개다.
- `E: 전망 보기` 안내는 플레이어가 전망점 반경 2.4m 안에 있을 때만 나타난다.
- E 진입 시 자동 이동·대기 클릭·목적지 표식을 취소하고 수평 이동을 잠근 뒤, 기존 카메라 스크립트를 정지한 동안 M01 제어기 하나가 0.9초 전망 전환을 수행한다.
- 전망 중 우클릭은 받지 않는다. E 또는 Esc로 복귀하며, WASD는 복귀 전환을 시작하고 전환이 끝나면 직접 이동을 다시 허용한다. 취소한 옛 목적지는 되살리지 않는다.
- 바다·빈 배경 클릭은 해안 장면에서만 목적지로 투영하지 않는다. 기존 P1의 빈 배경 보정 기본값은 유지한다.
- 추가 사용자 요청에 따라 M01 캐릭터는 높이 2.0, 반지름 0.55로 축소했다. M01의 충돌과 Agent도 같은 크기로 맞추고 평면 NavMesh 높이 관계에 맞춰 `path_height_offset=-0.5`를 사용한다.
- 평상 카메라는 정면축을 유지한 채 위치 `(0, 9.5, 14)`, X 회전 `-34.5°`로 더 높고 멀게 조정했다.
- 추가 사용자 요청에 따라 전망 진입 구도는 우측으로 틀지 않은 바다 정면축에서 아래를 살짝 내려다보며, 플레이어 윗부분만 화면 중앙 하단에 걸치는 구도로 조정했다. 전망 기준점의 앵커 `(0, 5.5, 1.5)`와 주시점 `(0, -0.5, -25)`, FOV `45°`를 사용한다.
- 전망 반경 안의 어느 위치에서 진입해도 앵커와 주시점이 플레이어 XZ만큼 함께 이동해 하단 중앙 구도를 유지한다. 복귀 시 평상 카메라 위치와 FOV `75°`를 복원한다.
- M01 플레이어·Agent 반지름 `0.55`에 비해 전용 NavMesh 베이크 반지름이 `1.0`으로 남아 있던 불일치를 확인해, 기본 셀 `0.25`의 안전한 배수인 `0.75`로 줄였다. 목책의 수평 충돌 크기도 보이는 메시와 같은 측면 `(0.28, 11.4)`, 끝면 `(17.5, 0.28)`로 맞추고 높이 차단은 유지한 뒤 M01 전용 NavMesh만 다시 베이크했다.
- `project.godot`에는 E용 `view_vista` 입력만 추가했고 기존 메인 씬과 Compatibility 렌더러를 유지했다.
- P0, `p1_movement.tscn`, 기존 P1 NavMesh와 카메라 스크립트는 변경하지 않았다. 공유 `p1_player.gd`의 새 옵션은 기본값에서 기존 P1 동작을 유지한다.

## M01 기술 확인

- Godot import와 스크립트 파싱, 해안 장면 헤드리스 로드: 오류 없음.
- 구현 순서는 기존 GLB 반입 → 해안 씬의 GLB 네 인스턴스 배치 → 기존 P1 플레이어·카메라 연결 → M01 전용 NavMesh와 전망 제어 연결 → 실행·기록 순으로 실제 파일에서 대조했다. 반입 파일만 있는 상태와 실행 장면 연결 완료 상태를 구분했으며 P0 상태로 되돌리지 않았다.
- M01 전용 NavMesh: 정점 31, 폴리곤 29, 시작점–전망점 경로 9점.
- 실제 카메라 레이를 사용한 우클릭 진단: 6.8m 이동, 목표 0.333m 안에서 정지, 표식 제거.
- 대표 수평 레이의 접점→실제 목적지/표식 간격은 수정 전 서쪽 목책 `1.250m`, 오른쪽 바위 `0.978m`였고 수정 후 각각 `0.860m`, `0.921m`였다. 표식은 NavMesh 경로의 실제 끝점과 오차 `0.0000m`로 일치해 별도 표식 오프셋은 없었다.
- 수정 후 실제 정지는 목책 접점 기준 중심 `1.143m`·몸통 표면 `0.593m`, 바위 접점 기준 중심 `0.876m`·몸통 표면 `0.326m`였다. 남은 간격에는 몸통 반지름 `0.55`, 베이크 안전 반지름 `0.75`, 셀 `0.25`의 래스터 경계와 도착 임계값 `0.35`가 포함되므로 안전 여유를 더 없애지 않았다.
- 빈 바닥 클릭은 의도점과 목적지 오차 `0.000m`, WASD의 자동 이동 취소, 전망 복귀 뒤 우클릭 이동은 목표 오차 `0.292m`와 표식 제거까지 다시 확인했다. 벽·바위 측면 진단은 실제 물리 레이 접점과 직접 목적지 함수 호출을 사용했고 OS 마우스 입력과는 구분한다.
- 서쪽 목책 방향 WASD 진단: 플레이어 중심 X `-7.933`에서 충돌 정지하고 경계 밖으로 빠지지 않음.
- 바다·빈 배경 목적지 거부 확인.
- 길가 바위 두 개의 월드 AABB 바닥 Y=0 접지, GLB 바위 네 인스턴스와 재질 표시 확인.
- E 진입과 E/Esc/WASD 각 복귀, 전망 중 우클릭 차단, 진입 시 옛 자동 이동·표식 취소 확인.
- 공유 플레이어 변경 뒤 P1 회귀: WASD 3.0m 이동, 우클릭 목표 오차 약 0.342m, 추적 카메라 위치 오차 약 0.003m로 정상.
- 일반 Compatibility 그래픽 렌더에서 평상·전망·복귀 화면 생성 성공. 평상 시점은 정면축의 높은 카메라에서 산책로, 축소된 캐릭터, 바위, 모래 해안, 바다와 원경을 표시한다.
- 전망 시점은 정면축을 유지한 채 카메라 전방 벡터 Y 약 `-0.221`로 아래를 향하고, FOV `45°`에서 바다와 원경이 중심을 차지하며 캡슐 윗부분만 화면 중앙 하단에 살짝 보이는 것을 실제 프레임으로 확인했다. 복귀 뒤 FOV `75°`와 이동 잠금 해제가 확인됐다.
- 시간차 전망 프레임 해시가 달라 바다 셰이더의 시간 기반 움직임이 계속됨을 확인했다.
- 기존 Intel HD Graphics 530 OpenGL 3.3 품질 경고와 ANGLE 전환은 유지됐다.
- Windows 화면 도구는 Godot 창의 동일한 앱 식별자를 소유권 불일치로 거부해 OS 입력 자동화는 완료하지 못했다. 대신 실제 일반 그래픽 렌더와 엔진 입력 이벤트·물리 진단을 수행했으며, 사람의 실제 키·마우스 확인과 구분한다.

## M01 사람 확인 묶음

1. 해안에서 WASD·우클릭으로 이동하고 보이는 경계 밖으로 빠지지 않는다.
2. 노란 표식 근처에서 E로 전망에 들어가고 E, Esc, WASD 각각으로 정상 복귀한다. 이후 우클릭도 정상 동작한다.
3. 평상 시점에서 축소된 캐릭터·바위·바다·원경이 자연스럽게 보이고, 전망 진입 시에는 우측 회전 없이 바다를 향해 살짝 내려다보며 플레이어 윗부분만 화면 중앙 하단에 보이고, 재실행해도 같은 장면이 동작한다.

최종 아트 적합성, 실제 플레이 크기 감각, 성능, 바위 충돌의 최종 형상, 상호작용·채집, 정식 월드 배치는 아직 미검증이다. 현재 상태는 `M01 — 해안·전망 통합 구현완료·사람확인대기`이며 stage/commit/push하지 않았다.
