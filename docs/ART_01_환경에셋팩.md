# ART-01 — Green Coast 첫 환경 에셋팩

## 상태

`ART-01 — 에셋 제작·지역 적용 완료·사람 확인 대기`

M02의 거점→숲→폐허→해안→귀환 흐름과 저장 구조를 유지하면서 `16_AI_입체픽셀_스타일가이드.md`의 초안을 첫 실제 화면 시험 기준으로 적용했다. 이번 결과는 최종 캐릭터·렌더러·해상도·팔레트 확정이 아니다.

## 실행

- 메인 장면: `res://scenes/prototype/green_coast_m02.tscn`
- Godot에서 F5 또는 위 장면을 F6로 실행한다.
- 이동·채집·제작·전시·절벽 전망과 저장 조작은 M02와 같다.

## 제작 기준과 ART-01 시험값

- 3D 공간, 단순한 큰 형태, 제한된 색, 픽셀 단위 표면 덩어리와 절제된 효과를 사용했다.
- 64×64 고정 패턴 텍스처 네 종류를 만들고 `Nearest with mipmaps` 재질 필터와 밉맵 생성 import 설정을 사용했다.
- 공유 재질은 석재, 절벽 석재, 목재, 잎, 흙길, 지면의 여섯 종류다.
- 석재는 UV가 없는 기존 B2 바위에도 적용되도록 별도 재질의 트라이플래너 투영을 사용했다. 원본 GLB와 원본 재질은 수정하지 않았다.
- 난수는 사용하지 않았다. 같은 제작 도구를 실행하면 같은 형태·색 패턴을 만든다.
- 화면 전체 픽셀화, 렌더러·카메라 변경, 후처리·새 광원·새 충돌은 추가하지 않았다.

## 텍스처와 재질

| 표면 | 텍스처 | 크기 | 표현 |
|---|---|---:|---|
| 석재 | `stone_pixel.png` | 64×64 | 큰 회녹색 면, 제한된 층과 균열색 |
| 목재 | `wood_pixel.png` | 64×64 | 판재 방향을 따르는 굵은 결 |
| 잎 | `leaf_pixel.png` | 64×64 | 불투명한 군집 단위 초록 명암 |
| 흙 | `soil_pixel.png` | 64×64 | 낮은 대비의 큰 흙색 덩어리 |

재질 기본색은 각 텍스처의 다섯 색 안에서 구성하고, 실제 재질 tint와 조명을 함께 사용한다. 석재 무늬는 첫 렌더에서 지나치게 촘촘해 보여 트라이플래너 반복 밀도를 `2.5→0.75`, 절벽은 `3.0→1.0`으로 낮췄다. 지면은 큰 무늬가 과도하게 늘어나지 않도록 반복 밀도 `6.0`, 흙길은 `2.5`를 사용했다.

## 지역 적용 결과

### 거점

- 오두막의 기존 충돌·크기는 유지하고 목재 벽, 잎색 지붕과 굵은 목재 문으로 표면을 통일했다.
- 벤치는 좌판·등받이·다리·연결부가 구별되고, 전시 받침은 석재 단과 밝은 유물이 분리되어 보인다.
- 기능 슬롯과 이동 통로에는 새 충돌 장식을 두지 않았다.

### 숲

- 구형 수관을 굵은 줄기와 세 개의 불투명 잎 덩어리로 바꿨다.
- 낮은 관목은 길 밖에만 소수 배치하고 목재·돌 채집물은 형태와 명도에서 배경과 구분했다.
- 기존 나무 충돌체와 채집 ID·상호작용 위치는 유지했다.

### 폐허

- 차가운 석재 픽셀 무늬를 벽·아치·잔해에 공유해 장소를 묶었다.
- 잔해 두 군집은 출입구와 유물 접근선 밖에 두었고 별도 충돌을 만들지 않았다.
- 유물의 청록 강조색과 기존 상호작용 조건은 유지했다.

### 해안과 전망

- B2 바위에는 인스턴스 override로 같은 석재 무늬를 적용하고, 북쪽 절벽에는 세 층의 큰 면을 반복 배치했다.
- 바다 셰이더와 수평선 여백, 전망 카메라와 절벽 접촉 범위는 바꾸지 않았다.
- 실제 전망 프레임에서 원경 바위의 무늬와 실루엣이 보이고 플레이어 윗부분·복귀 안내를 가리지 않았다.

## 기능·저장 보존

- 기존 아홉 개 획득 ID, 획득량, 벤치 비용, 전시 조건과 저장 스키마를 바꾸지 않았다.
- 채집물은 기존 루트의 `visible/active` 상태에 따라 함께 사라진다.
- 벤치와 전시 받침은 기존 설치·전시 상태가 참일 때만 보인다.
- 플레이어 루트·캡슐·속도·높이 보정, 카메라·전망 로직, NavMesh와 경계 충돌은 수정하지 않았다.
- 실제 사용자 저장은 읽기 전용으로 복사한 격리 경로에서 이어하기 표시를 확인했으며 원본 파일은 덮어쓰지 않았다.

## 기술 확인

- 제작 도구 실행: 텍스처 4, 재질 6, 시각 씬 9 생성 성공.
- 텍스처 크기, 재질 참조, Nearest 계열 필터와 밉맵 import 설정 확인.
- 열 번째 자산인 기존 B2 바위는 삼각형 46개로 원본 형상이 유지됐다.
- M02 NavMesh는 정점 112, 폴리곤 116으로 변경되지 않았다.
- 실제 물리 프레임의 WASD, 직접 우클릭 엔진 이벤트 이동, 절벽 전망 진입·이탈을 확인했다.
- 격리 신규 상태에서 목재·돌·유물 획득, 벤치 설치와 유물 전시 후 외형 상태를 확인했다.
- 격리 저장 후 이어하기와 실제 사용자 저장의 읽기 전용 복사본에서 상태와 시각 표시가 일치했다.
- 메인 M02, 비교용 M01, P1 장면이 모두 헤드리스로 오류 없이 열렸다.
- 1280×720 일반 Compatibility 렌더에서 거점·숲·폐허·전망 화면을 직접 확인했다. 기존 Intel HD 530의 ANGLE 전환 경고만 남았다.

우클릭 확인은 Godot 내부 입력 이벤트를 직접 전달한 진단이며 실제 OS 마우스 조작과 구분한다. 자동화한 수치는 최종 스타일·성능·재미 판정이 아니다.

## 재생성 방법

정상 체크아웃에서는 다음 도구를 명시적으로 한 번 실행하면 고정 자산을 재생성한다.

`C:\godot\godot.exe --headless --path C:\Users\CKIRUser\RPGpro --script res://tools/art_01_build.gd --rendering-method gl_compatibility`

텍스처 원본부터 새로 만드는 복구 상황에서는 `-- --textures-only`로 PNG를 먼저 생성하고 Godot import를 마친 뒤 전체 도구를 실행한다. 출력은 위 ART-01 자산·장면 경로에만 한정된다.

## 사람이 확인할 세 묶음

1. **스타일:** 거점·숲·폐허·해안이 같은 게임으로 보이면서 장소 차이가 느껴지고, 목재·석재·식생 무늬가 지나치게 지저분하지 않은가?
2. **플레이:** 이동·목적지 표식·상호작용 안내가 가려지지 않고, 재료 획득·벤치 설치·기념품 전시가 기존처럼 동작하는가?
3. **보존·전망:** 계속하기와 재실행 뒤 상태가 유지되고, 절벽 전망에서도 바위·절벽 무늬가 너무 얇거나 깨져 보이지 않으며 풍경을 방해하지 않는가?

## 미확인·후속 조정

- 최종 팔레트와 픽셀 밀도, 최종 캐릭터 외형과 렌더러·후처리는 미정이다.
- 실제 OS 키·마우스의 전체 동선 체감과 장시간 프레임 성능은 사람이 확인해야 한다.
- 사람 확인에서 무늬가 강하거나 약하다고 판단되면 공유 재질의 tint·반복 밀도를 먼저 조정하고 새 파이프라인을 추가하지 않는다.
- 이번 결과는 첫 지역용 한 팩이며 다음 지역·가구 테마를 자동 생산하지 않는다.
