# P1-2 우클릭 이동

## 목표

작은 P1 시험장에서 유효한 바닥을 우클릭하면 캡슐이 고정 장애물을 피해 목적지까지 이동하고, WASD 입력이 들어오면 즉시 직접 조작으로 전환되는지 확인한다.

## 이번 시험 선택

- 우클릭 `move_to_point` 한 번으로 유효한 바닥 목적지를 교체한다. 명령 큐는 없다.
- 카메라 레이가 처음 만난 충돌체가 명시적으로 연결된 이동용 바닥이고 윗면일 때만 목적지 후보로 삼는다.
- 클릭점은 NavMesh에서 수평 0.75 이내로만 보정하며, 도달 경로의 끝점이 목적지와 일치할 때만 수락한다.
- 자동 이동은 P1-1의 속도 4.0, 중력과 `move_and_slide()` 처리를 함께 사용한다.
- 도착 수평 거리 0.35 이내에서 정지하고 표식을 숨긴다.
- 1.5초 동안 수평 진행이 없으면 명령당 한 번 경고하고 자동 이동을 중단한다.
- WASD 키 하나라도 눌리면 상반된 키로 이동 벡터가 0이어도 자동 이동·대기 클릭·표식을 취소한다.
- 내비게이션 맵 iteration이 준비되기 전 클릭은 저장하거나 나중에 재생하지 않는다.
- 정적 NavMesh는 `scenes/prototype/p1_navigation_mesh.tres`에 보존하며 고정 상자와 외곽 막이를 반영한다.
- 목적지 표식은 충돌이 없는 엔진 내장 메시 하나이며 플레이어의 자식이 아니다.

이 규칙은 P1-2 시험용이다. 우클릭과 WASD의 최종 병행 여부, 공격·채집·상호작용, 동적 장애물, 최종 캐릭터·카메라는 확정하지 않는다.

## FIX-01 — 사용자 실패 보고와 수정

- 최초 상태: `P1-2 — 사람 확인 실패·수정 중 (표식만 표시, 자동 이동 없음)`.
- 사용자 직접 확인: 기존 WASD 이동은 됐고, 우클릭 목적지 표식은 나타났으며, WASD를 누르면 표식이 사라졌다. 우클릭만 했을 때 캡슐은 이동하지 않았다.
- 확인 원인: 캡슐 제어 원점 Y=1.4와 NavMesh 경로면 Y=0.5 사이의 높이 차이 0.9 때문에 `NavigationAgent3D`가 첫 경로점을 `path_desired_distance=0.35` 안에 도달한 것으로 처리하지 못했다. 첫 경로점의 XZ는 현재 위치와 같아서 플레이어의 수평 이동 방향은 0으로 남았고, 경로 인덱스 0에서 1.5초 무진행 종료됐다.
- 최소 수정: `p1_movement.tscn`의 기존 Agent에 `path_height_offset=-0.9`를 지정해 경로 추종 높이를 캡슐 제어 원점에 맞췄다. 이 값은 현재 시험 캡슐의 원점과 현재 NavMesh 경로면 관계에 따른 설정이며 다른 캐릭터·지역의 공통값이 아니다. 속도·도착 거리·무진행 시간, WASD 처리, 충돌, NavMesh와 베이크 도구는 바꾸지 않았다.
- 단발 진단: 실제 `p1_movement.tscn`과 실제 `Player`를 인스턴스화하고 화면 우클릭 대신 기존 `_try_accept_destination()`을 호출했다. 열린 바닥에서는 100 물리 프레임 동안 6.67 이동해 목표 수평 거리 0.333에서 정지했고, 왼쪽 고정 상자 뒤 목표에는 6개 경로점을 따라 159 프레임에 수평 거리 0.346에서 정지했다. 자동 이동 중 `Input.action_press("move_right")`를 주입하면 표식과 자동 이동이 취소되고, 키 해제 뒤 20프레임 동안 옛 목표로 재출발하지 않았다.
- 사용자 재확인: 수정 후 실제 실행에서 “확인 완료. 이제 경로 탐색해서 잘 움직임”을 확인받았다. 이는 실제 우클릭 경로 이동 불가 오류가 해소됐다는 사람 확인이며, 아래 표의 모든 세부 사례를 함께 확인했다는 뜻은 아니다.
- 현재 상태: `P1-2 — 핵심 경로 이동 사람 재확인 완료`. 위 기술 진단과 실제 우클릭 사용자 확인을 구분하며 목적지 교체·무효 클릭 등 남은 항목은 계속 미확인이다.

## 기술 확인

- Godot `4.7.2.stable.official.ed1daf0bf`에서 프로젝트 import, GDScript 파싱과 메인 씬 12회 반복 로드: 오류 없이 완료.
- 정적 NavMesh 최종 베이크: 정점 23개, 폴리곤 25개. 왼쪽 고정 상자의 앞뒤를 잇는 경로 질의가 직선 관통 대신 6개 경로점으로 우회하는 것을 확인했다.
- 베이크 중 처음 사용한 0.2/0.1 셀 설정은 기본 내비게이션 맵과 불일치·정밀도 경고가 있어 0.25 단위로 맞췄다. 실제 캡슐 반경 0.75·높이 2.8에 대해 베이크 여유를 둔 반경 1.0·높이 3.0으로 최종 베이크했으며 해당 경고 없이 완료됐다.
- 첫 경로 확인은 테스트 맵의 NavMesh 연결 동기화 전 질의해 빈 경로로 실패했다. iteration을 직접 확인하고 추가 동기화한 뒤 iteration 2에서 우회 경로를 확인했으며, 준비 전 질의를 성공으로 처리하지 않았다.
- 일반 그래픽 Compatibility 실행과 정상 종료: 완료. 기존 Intel HD Graphics 530의 OpenGL 3.3 품질 경고와 ANGLE 전환은 유지됐고 새 씬·스크립트 오류는 없었다.
- `move_to_point` 우클릭 액션, 기존 WASD 네 액션, 명시적 바닥 판정·경로 끝점 확인·WASD 취소와 한 물리 프레임의 단일 `move_and_slide()` 호출을 확인했다.
- P0 원본 `p0_bootstrap.tscn`은 Git diff가 없고, 기존 WASD 방향 변환·속도·중력·충돌 처리도 유지했다.
- 엔진 생성 보조 파일: `tools/p1_bake_navigation.gd.uid`. `.godot/` 캐시와 구분한다.
