# P1-4 우클릭 목적지 보정

## 목표

현재 단층 P1 시험장에서 빈 바닥을 정밀하게 맞히지 않아도 클릭 의도에 가까운 도달 가능한 위치를 골라 기존 경로 이동으로 도착한다.

## 이번 시험 규칙

- 빈 바닥은 실제 접점을 의도점으로 사용한다.
- 현재 `NavigationRegion3D` 아래의 고정 상자와 외곽 막이는 첫 충돌 접점의 XZ를 실제 이동 바닥 윗면으로 투영한다. 물체 중심이나 상자 위를 목적지로 쓰지 않는다.
- 아무 물리 표면도 맞히지 않은 화면 안 레이는 실제 바닥 충돌체에서 계산한 기준 평면과 교차시킨다. 평행·뒤쪽·비정상 값·1000보다 먼 교점은 거부한다.
- 의도점에서 실제 NavigationAgent 맵의 가까운 점을 구하고, Agent의 `navigation_layers`로 현재 위치부터 경로를 조회한다. 비어 있지 않은 경로의 실제 끝점을 최종 목적지로 사용한다.
- 최종 목적지와 표식은 수락 뒤 월드 위치에 고정한다. 표식은 실제 바닥 윗면 Y=0 위의 Y=0.04에 표시한다.
- 지원하지 않는 첫 충돌체, 유효하지 않은 레이·경로와 내비게이션 준비 전 입력은 새 명령을 만들지 않고 기존 목표·표식을 유지한다.
- 새 유효 목표 교체, WASD 우선 취소, 도착·무진행 처리와 기존 속도·중력·충돌은 유지한다.

여기서 “가까운 최적점”은 전역 최단거리 해답이 아니라 현재 평면 시험장의 연결된 내비게이션 영역에서 엔진이 돌려준 도달 가능한 경로 끝점이다. 이 평면 교차 방식은 절벽·계단·다층 집·바다·Vista에 자동 적용하지 않는다.

## 사용자 확인

- 실제 실행에서 사물 클릭 시 가까운 도달 가능 위치로 이동하는 것을 확인했다.
- 실제 실행에서 벽 클릭 시 안쪽 도달 가능 위치로 이동하는 것을 확인했다.
- 현재 기록 상태: `P1-4 — 사물·벽 목적지 보정 사용자 확인 완료`.
- 이 확인은 바닥 밖 배경, 모든 윗면·측면의 개별 사례, 목적지 변경·WASD 취소, 진짜 무효 입력, 근접 목표와 재실행까지 확인했다는 뜻은 아니다. 아래 기술 진단의 좌표·표식 높이도 사용자가 직접 측정한 값으로 바꾸지 않는다.

## 여는 방법

1. Godot에서 `C:\Users\CKIRUser\RPGpro` 프로젝트를 연다.
2. F5로 기존 `res://scenes/prototype/p1_movement.tscn`을 실행한다.
3. 빈 바닥, 상자 윗면·측면, 외곽 벽과 게임 화면 안의 바닥 밖 배경을 각각 우클릭한다.
4. 이동 중 새 보정 목표와 WASD 취소를 확인하고 F8/F5로 다시 실행한다.

## 사람 확인 목록

| 확인 | 기대 | 금지 | 상태 |
|---|---|---|---|
| 빈 바닥/상자 뒤 빈 바닥 | 기존 정확한 이동·우회·도착 | 원래 잘 되던 클릭이 가까운 엉뚱한 점으로 바뀜 | 미확인 |
| 상자 윗면·측면 직접 클릭 | 가까운 실제 바닥에 표식, 경로 이동 후 정지 | 표식이 공중/상자 안에 생김, 상자에 영구 밀기 | 부분 확인 — 사물 클릭 이동; 윗면·측면 각각의 세부는 미확인 |
| 외곽 벽 직접 클릭 | 걸을 수 있는 안쪽 가장자리로 이동 | 벽 관통, 시험장 밖 이동 | 사람 확인 — 벽 클릭 이동 |
| 게임 화면 안 바닥 밖 배경 클릭 | 바닥 기준 교점이 유효하면 그 쪽 가장자리로 보정 | 아무 반응 없음을 성공으로 처리, 원점 이동, 경계 밖 목표 | 미확인 |
| 목적지 변경/직접 조작 취소 | 보정 목표도 새 유효 클릭으로 교체, WASD 취소 후 재출발 없음 | 큐가 남음, 두 이동 힘이 더해짐 | 미확인 |
| 진짜 무효 입력 | 기존 유효 목표를 유지하고 새 명령 없음 | 임의 목표·표식 변경 | 미확인 |
| 추적 중 클릭/도착/재실행 | 클릭 순간 기준 보정, 표식 월드 고정, 정지 안정, 재실행 후 동일 | 카메라에 표식이 끌림, 높이 오류 재발, 무한 반복 | 미확인 |

실제 화면 입력과 체감은 사람이 확인한다. 게임 재미와 전 지역·다층·동적 장애물 지원은 이번 통과 범위가 아니다.

## 기술 확인

- Godot `4.7.2.stable.official.ed1daf0bf`에서 import, GDScript 파싱과 메인 씬 짧은 headless 로드: 오류 없이 완료.
- 실제 P1 씬의 저장된 화면 레이를 직접 주입해 기존 물리 조회·목적지 수락·CharacterBody3D 이동을 실행했다. 이는 OS의 실제 마우스 클릭을 재현한 것은 아니다.
- 빈 바닥 접점 `(0, 0, -3.5)`은 NavMesh 목적지 `(0, 0.5, -3.5)`로 수락되어 수평 6.667 이동하고 남은 거리 0.333에서 정지했다.
- 왼쪽 상자 윗면 접점 `(-3, 1.8, -1.273)`은 `(-3, 0.5, -3)`으로, 측면 접점 `(-3.274, 0.279, -0.1)`은 `(-3.274, 0.5, 1)`로 보정됐다. 각각 실제 이동 후 남은 거리 0.338과 0.349에서 정지했다.
- 북쪽 외곽 막이 접점 `(-0.288, 0.700, -5.4)`은 안쪽 `(-0.288, 0.5, -4.25)`로 보정되어 수평 5.543 이동하고 남은 거리 0.301에서 정지했다.
- 물리 표면이 없는 레이의 바닥 평면 교점 `(-48.841, 0, -81.938)`은 시험장 안쪽 NavMesh 끝점 `(-6.25, 0.5, -4.25)`로 보정되어 수평 5.6 이동하고 남은 거리 0.319에서 정지했다.
- 뒤쪽을 향한 무효 레이는 진행 중 목표·표식을 바꾸지 않았고, 이어진 WASD 입력은 자동 이동과 표식을 취소했다. Agent `path_height_offset=-0.9`와 P1-3 카메라 스크립트·반응 속도는 바꾸지 않았다.
- 진단용 임시 스크립트는 제거했다. 화면 클릭 감각과 위 사람 확인 목록은 사람 확인 대기다.
