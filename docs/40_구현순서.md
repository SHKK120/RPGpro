## 현재 재개 지점 — SCENARIO-01 실제 연결 확인

- 상태: **공식 Scenario Skill 11개 + RPGpro Director + Reference Registry + 생산 계약 준비 완료 / MCP 재시작·OAuth·실제 연결 진단 대기**.
- `.codex/config.toml`에 공식 URL과 OAuth를 등록했지만 현재 프로세스는 설정 변경 전 도구 목록을 사용한다. 관리형 PC의 `codex mcp` CLI `EPERM`은 우회하지 않는다.
- 다음 행동: 새 Codex 작업 또는 MCP 재시작 → OAuth → diagnostics → Team/Project → lean live image model/asset/collection tool discovery. 여러 Team/Project면 임의 선택하지 않는다.
- 연결 확인 뒤에도 가능한 모든 과금 호출에 `dry_run`을 먼저 사용한다. 첫 credit-consuming generation 전 예상 CU와 Asset별 누적 CU 상한을 보고하고 사용자 승인을 기다린다. 자동 후보 1장·기본 Refine 1회이며 Model Training은 별도 승인이 필요하다.
- 승인 후 첫 E2E 후보는 Tree A, Medium Rock, Ruin Arch 세 종류 이하다. 세 자산의 실제 Gameplay Camera 사람 확인 전에는 대량 생산하지 않는다. PASS PNG만 Godot Sprite3D와 별도 Collision Proxy로 결합한다.
- 사용자가 2026-09-07 SCENARIO-01까지의 정본 체크포인트 백업을 승인했다. 프로젝트 코드·Scene·Material·reference·대표 review PNG·문서·프로젝트 Skill만 선별하고 `.codex`, 인증정보, cache, 로그와 Movie Maker 연속 프레임은 제외한다. 원격 `origin/main`이 새 로컬 HEAD와 일치하는지 확인한 뒤 초기화 복구 정본으로 취급한다.
- 상세 정본: `SCENARIO_01_Production_Pipeline.md`, `art/SCENARIO_REFERENCE_REGISTRY.md`.

## [제안] 첫 구현 논의를 위한 초안 순서

1. P0 실행 기반: 지정 Godot에서 최소 3D 화면이 뜨고 다시 열리는지 확인한다. 바닥, 조명, 카메라, 임시 물체 수준이다.
2. P1 이동·시각 시험: 최소 이동과 기본 카메라를 만들고, 별도 작은 조각에서 언덕, 바다, Vista를 시험한다.
3. P2 행동·보상: 채집 한 종류 → 획득·보관 → 가구 한 종류 배치·회수로 나눈다.
4. P3 보존: 최소 저장/로드를 확인한 뒤 같은 배치 영역의 집터 두 곳 사이 이전을 검증한다. 외부 배치는 관련 규칙을 닫은 뒤 확인한다.
5. P4 전투·성장: 확정한 전투 초안으로 적 하나와 업그레이드 하나부터 시작하고, 보스와 트로피는 그 뒤에 연결한다.
6. 첫 완결 루프: 탐험 → 위험·보상 → 귀환 → 성장·꾸미기가 이어진 뒤 사람이 판정한다.

각 묶음은 한 세션짜리 조각이 아닐 수 있다. 실제 착수할 때 화면 요소로 나누고 되는 경우와 안 되어야 하는 경우의 확인 목록을 먼저 쓴다. 기계적 성공, 사용성, 시각 만족, 재미는 별도로 평가한다. 이 순서는 구현 승인이 아니며 P0로 자동 진행하지 않는다.
