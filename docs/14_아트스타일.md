# 아트 스타일

## 문서의 역할

게임의 시각적 방향과 표현 원칙을 정의한다.

## 이 문서가 소유하는 정보

- 그래픽 스타일의 원칙
- 카메라 표현 원칙
- Vista의 시각적 표현과 보상감에 관한 방향

## 이 문서가 소유하지 않는 정보

- 게임 플레이 수치
- 지역별 콘텐츠 데이터
- 그래픽 구현 코드

## [요구·채택 방향]

- 3D 깊이, 광활한 바다·석양·전망, 평소 플레이를 방해하지 않는 특별 카메라 연출이 중요하다.
- Low-poly와 픽셀풍·저해상도 텍스처를 기반으로 조명, 물, 안개, 파티클을 조합하는 방향을 목표로 한다.

## [제안]

- 기본 카메라는 높은 쿼터뷰 계열로 두고 Vista에서 제한적으로 구도를 바꾼다.
- 먼저 작은 시각 시험 구간 하나에서 기본 시점과 전망 시점을 함께 확인한다. 전체 월드를 꾸민 뒤 검증하지 않는다.

## [미정]

- 캐릭터를 3D 모델과 2D 스프라이트 중 무엇으로 표현할지
- 투영 방식, 카메라 조작과 각도
- 화면 전체의 저해상도 렌더링 여부
- 텍스처 해상도와 팔레트
- 렌더러와 성능 기준

480×270 렌더링이나 모든 텍스처를 32×32로 만드는 과거 예시는 강제 규격으로 이관하지 않는다.

## [제안] 에셋 파이프라인

- 최종 게임 에셋과 생성 후보·편집 원본을 분리한다.
- 생성 결과는 크기, 방향, 피벗, 충돌, 실루엣, 재질을 확인한 뒤 채택한다.
- Meshy와 Higgsfield 등은 제작 도구 후보이며 게임 실행 의존성이 아니다. 이번 단계에서는 결제, 연결, 다운로드하지 않는다.
- GitHub에는 실행에 필요한 정본을, Drive에는 원본과 후보를 두는 방향이다.
- Git LFS의 사용 범위, 용량, 비용은 실제 에셋이 생길 때 별도로 정한다. 대형 생성 원본을 저장소에 일괄 추가하지 않는다.
