# 아트 스타일

## SCENARIO-01 일관성 생산 규칙

- 최신 승인 reference가 있으면 bare text prompt 대신 `Canonical Reference → Approved Asset ID → Control → Baseline + Delta → Quality Gate → Targeted Refine`를 우선한다.
- Environment Sprite는 실제 Green Coast Camera family(perspective, FOV 52, pitch -27도)를 기준으로 단일 물체·투명 배경·bottom-centre 접지·균일 scale·무텍스트 출력 계약을 따른다.
- Godot/Blender proxy는 scale·footprint·silhouette·orientation을 전달하며, Scenario는 visual만 만들고 Collision/NavMesh/Gameplay Geometry를 결정하지 않는다.
- 환경 Style과 Character Identity를 분리한다. 주인공·몬스터는 현재 제작하지 않으며 캐릭터 시트는 향후 identity 참고로만 보존한다.
- 13항목 Quality Gate PASS와 실제 Gameplay Camera 비교를 통과한 PNG만 반입한다. 자동 후보는 기본 1장, Refine은 기본 1회이며 2회째는 명확한 실패 원인과 CU 상한 안에서만 허용한다. 첫 credit 소비와 model training은 각각 사용자 승인이 필요하다.
- 상세 규칙과 reference 역할은 `SCENARIO_01_Production_Pipeline.md`, `art/SCENARIO_REFERENCE_REGISTRY.md`가 소유한다.

## MASTER-03R 현재 시각 구조 — 3D Gameplay + 2.5D Visual

- 현재 우선 구조는 실제 3D Ground·Cliff·Ramp·Stairs·Collision·NavMesh 위에 환경 visual을 Sprite3D/AnimatedSprite3D로 조립하는 2.5D 방식이다.
- 집·유적·대형 절벽은 필요할 때 단순 3D foundation과 2.5D 전면을 결합한다. 기존 MASTER-03 전체 3D 결과는 보존하되 저품질 visual mesh는 교체 후보로 분류한다.
- 최신 첨부 이미지가 과거 ART-01보다 우선한다. `test.png`는 조립 목표, `test2.png`는 Material/Transition/Module 규격 기준으로 사용하며 판넬 전체와 텍스트를 게임에 넣지 않는다.
- Grass, Soil/Path, Rock Cliff, Sand, Shallow Water 표면 샘플은 독립 재질로만 사용한다. 넓은 바닥과 암벽은 Texture를 늘이지 않고 고정 월드 타일 크기로 이어 붙이며, 원본 비율·UV 양축 반복·Transition 이음새를 실제 Godot 화면에서 검사한다.
- 주인공·몬스터를 디자인하지 않는다. 방향 표시용 기술 marker와 4/8방향 구조만 준비한다.
- 상세 구조와 검증 결과는 `MASTER_03R_2D5D_Visual_Architecture.md`가 소유한다.

## MASTER-03 실제 Green Coast Production Build

- MASTER-02R의 형태·팔레트·재질 언어를 실제 F5 Green Coast에 적용했다. 현재 사람 확인 대상은 독립 Reference Area보다 `green_coast_m02.tscn`의 Home, Cliff, Ruins, Beach, Vista 실제 gameplay frame이다.
- Production Kit은 82 reusable scene과 22 shared Material로 확장됐다. 실제 플레이어 높이 2.0m와 4m module connection을 기준으로 건물·길·절벽·식생·폐허·해안을 조립한다.
- 실환경 첫 렌더에서 roof/accent가 밝은 주황으로 읽힌 문제를 shared material 단계에서 어두운 terracotta로 보정했다.
- 주인공·몬스터는 디자인하지 않았다. 현재 placeholder와 전투 실루엣은 기능 보존 대상이며 최신 Character/Monster sheet의 느낌은 이후 제작 메모로만 유지한다.
- 상세 제작·통합·검증과 사람 확인 항목은 `MASTER_03_Green_Coast_Production_Build.md`가 소유한다.

## MASTER-02R Visual Production Baseline — 현재 제작 방향

- 최신 정본 이미지는 `art/reference/`의 Gameplay Visual Target, Green Coast Layout Target, Terrain/Nature/Village & Ruins 모듈 시트다. 이 이미지가 ART-01보다 현재 시각 판단 우선순위가 높다.
- 현재 방향은 **Bright & Warm Stylized Low-Poly Fantasy Adventure 3D**다.
- 큰 형태와 명확한 실루엣, 제한된 색상, Color Block, 단순하고 깨끗한 공유 Material, 절제된 Texture, 환경과 캐릭터의 비슷한 Detail Density를 우선한다.
- 제작 판단 순서는 `Gameplay Target → Layout → Asset Family → Silhouette → Geometry → Base Color → Material → Lighting → 필요한 최소 Texture → Godot 실제 화면`이다.
- Pixel influence는 보조다. 64×64, Nearest, 억지로 깨져 보이는 Texture를 전체 기본값으로 사용하지 않는다.
- MASTER-02의 제작 구조는 `MASTER_02_Visual_Production_Baseline.md`, 현재 보정 결과와 사람 확인 후보는 `MASTER_02R_Visual_Production_Baseline_Correction.md`가 소유한다.
- 이번 MASTER-02에서는 주인공과 몬스터를 디자인·모델링하지 않는다. 제공된 관련 시트는 향후 분위기·상대 스케일·파생 구조 참고로만 보존한다.

## M05 / ART-01 Visual Baseline — 과거 기술 시험

- 당시 기준선은 저폴리 3D 실루엣, 제한된 저해상도 텍스처, 낮은 채도의 자연색과 소수의 기능성 강조색을 조합했다.
- 제작 판단 순서는 `Reference → Silhouette → Color → Material → Lighting → Effects → Godot 실제 화면`이다. 작은 화면에서 역할과 진행 방향이 먼저 읽혀야 한다.
- 플레이어는 청록 상의·황토 후드/망토·밝은 얼굴, 적은 낮고 넓은 근접형·떠 있는 원거리형·방패 직립형 정예·대형 가면형 보스로 실루엣을 구분한다.
- M05에서는 2D 픽셀 단면 교체 가능성을 시험하기 위해 마우스 월드 방향을 8방향으로 양자화하고 이동·공격 방향 상태를 분리했다. 이는 과거 기술 시험이며 현재 캐릭터 최종 방식 확정이 아니다.
- 캐릭터 재질은 Cloth/Outer Cloth/Leather/Skin/Metal 슬롯으로 나누고 UV가 있는 기본 메시와 최근접 Mipmap 필터 기준을 사용해, 이후 8방향 텍스처·스프라이트를 붙일 때 이동·충돌·전투 루트를 바꾸지 않게 한다.
- 환경 재질군은 Ground/Soil/Stone/Cliff/Wood/Leaf/Ruin/Shore/Water를 공유하고, Accent는 상호작용과 보상에만 제한한다.
- Gameplay/Home/Vista 세 프레임을 대표 비교 대상으로 삼는다. 한 프레임의 최대 품질보다 전체 게임에 반복 적용 가능한 품질과 비용을 우선한다.
- 바다는 Compatibility에서 동작하는 낮은 진폭의 정점 파동과 넓은 색 띠까지만 사용한다. 실시간 반사, 고비용 안개, 과도한 발광은 기준선에 포함하지 않는다.
- 이 항목은 보존된 과거 기술 시험이며 최신 시각 정본이 아니다. 당시 세부 내용은 `MASTER_01_Visual_to_Game_Skeleton.md`를 따른다.

## 문서의 역할

게임의 시각적 방향과 표현 원칙을 정의한다.

## 이 문서가 소유하는 정보

- 그래픽 스타일의 원칙
- 카메라 표현 원칙
- Vista의 시각적 표현과 보상감에 관한 방향

## 이 문서가 소유하지 않는 정보

- 게임 플레이 수치
- 지역별 콘텐츠 데이터
- 그래픽 구현 코드

## [요구·채택 방향]

- 3D 깊이, 광활한 바다·석양·전망, 평소 플레이를 방해하지 않는 특별 카메라 연출이 중요하다.
- Stylized Low-Poly 3D의 큰 형태, 따뜻하고 밝은 색 덩어리와 단순한 재질을 기반으로 조명, 물, 안개, 파티클을 절제해 조합한다.
- 현재 시각 방향은 **Bright & Warm Stylized Low-Poly Fantasy Adventure 3D**다. Pixel influence는 일부 색·형태 절제에만 보조적으로 남는다.
- 플레이 가독성, 3D 공간감과 AI 반복 제작의 지속 가능성을 우선한다.

## 세부 실행 가이드

- AI가 지역·오브젝트·가구·거점 후보를 만들고 채택할 때는 최신 MASTER-02 기준을 우선하고 `16_AI_입체픽셀_스타일가이드.md`의 충돌하지 않는 제작·검증 원칙을 참고한다.
- 이 문서는 상위 시각 원칙을, 16번 문서는 형태·색·재질·조명·지역 적용·AI 제작과 채택 체크리스트를 소유한다.
- 16번 문서는 실행용 초안이므로 최종 캐릭터 방식, 해상도·필터링, 렌더러·후처리와 물 표현 등 기존 `[미정]`을 자동 확정하지 않는다.

## [제안]

- 기본 카메라는 높은 쿼터뷰 계열로 두고 Vista에서 제한적으로 구도를 바꾼다.
- 먼저 작은 시각 시험 구간 하나에서 기본 시점과 전망 시점을 함께 확인한다. 전체 월드를 꾸민 뒤 검증하지 않는다.

## [미정]

- 2D 픽셀 단면의 정확한 해상도, 보행·공격 프레임 수와 대각선 실루엣
- 투영 방식, 카메라 조작과 각도
- 화면 전체의 저해상도 렌더링 여부
- 필요한 Texture의 해상도·filtering과 최종 팔레트
- 렌더러와 성능 기준

480×270 렌더링이나 모든 텍스처를 32×32로 만드는 과거 예시는 강제 규격으로 이관하지 않는다.

## [제안] 에셋 파이프라인

- 최종 게임 에셋과 생성 후보·편집 원본을 분리한다.
- 생성 결과는 크기, 방향, 피벗, 충돌, 실루엣, 재질을 확인한 뒤 채택한다.
- Meshy와 Higgsfield 등은 제작 도구 후보이며 게임 실행 의존성이 아니다. 이번 단계에서는 결제, 연결, 다운로드하지 않는다.
- GitHub에는 실행에 필요한 정본을, Drive에는 원본과 후보를 두는 방향이다.
- Git LFS의 사용 범위, 용량, 비용은 실제 에셋이 생길 때 별도로 정한다. 대형 생성 원본을 저장소에 일괄 추가하지 않는다.
