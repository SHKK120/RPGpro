# 아트 스타일

## M05 Visual Baseline — 구현 기준선

- 현재 기준선은 저폴리 3D 실루엣, 제한된 저해상도 텍스처, 낮은 채도의 자연색과 소수의 기능성 강조색을 조합한다.
- 제작 판단 순서는 `Reference → Silhouette → Color → Material → Lighting → Effects → Godot 실제 화면`이다. 작은 화면에서 역할과 진행 방향이 먼저 읽혀야 한다.
- 플레이어는 청록 상의·황토 후드/망토·밝은 얼굴, 적은 낮고 넓은 근접형·떠 있는 원거리형·방패 직립형 정예·대형 가면형 보스로 실루엣을 구분한다.
- 캐릭터의 최종 시각 자식은 2D 픽셀 단면을 사용한다. M05에서는 마우스 월드 방향을 8방향으로 양자화해 이동·공격 방향 상태를 먼저 고정하고, 현재 저폴리 시각 자식은 교체 전 동작 검증용으로만 유지한다.
- 캐릭터 재질은 Cloth/Outer Cloth/Leather/Skin/Metal 슬롯으로 나누고 UV가 있는 기본 메시와 최근접 Mipmap 필터 기준을 사용해, 이후 8방향 텍스처·스프라이트를 붙일 때 이동·충돌·전투 루트를 바꾸지 않게 한다.
- 환경 재질군은 Ground/Soil/Stone/Cliff/Wood/Leaf/Ruin/Shore/Water를 공유하고, Accent는 상호작용과 보상에만 제한한다.
- Gameplay/Home/Vista 세 프레임을 대표 비교 대상으로 삼는다. 한 프레임의 최대 품질보다 전체 게임에 반복 적용 가능한 품질과 비용을 우선한다.
- 바다는 Compatibility에서 동작하는 낮은 진폭의 정점 파동과 넓은 색 띠까지만 사용한다. 실시간 반사, 고비용 안개, 과도한 발광은 기준선에 포함하지 않는다.
- 이 항목은 구현된 시각 기준선이며 최종 취향 판정은 사람 확인 대기다. 세부 내용은 `MASTER_01_Visual_to_Game_Skeleton.md`를 따른다.

## 문서의 역할

게임의 시각적 방향과 표현 원칙을 정의한다.

## 이 문서가 소유하는 정보

- 그래픽 스타일의 원칙
- 카메라 표현 원칙
- Vista의 시각적 표현과 보상감에 관한 방향

## 이 문서가 소유하지 않는 정보

- 게임 플레이 수치
- 지역별 콘텐츠 데이터
- 그래픽 구현 코드

## [요구·채택 방향]

- 3D 깊이, 광활한 바다·석양·전망, 평소 플레이를 방해하지 않는 특별 카메라 연출이 중요하다.
- Low-poly와 픽셀풍·저해상도 텍스처를 기반으로 조명, 물, 안개, 파티클을 조합하는 방향을 목표로 한다.
- 현재 시각 방향은 **3D 공간 + 단순한 형태 + 픽셀풍 질감·색감 + 절제된 현대 효과**를 결합한 입체감 있는 픽셀풍 3D 하이브리드다.
- 엄격한 픽셀 퍼펙트보다 플레이 가독성, 3D 공간감과 AI 반복 제작의 지속 가능성을 우선한다.

## 세부 실행 가이드

- AI가 지역·오브젝트·가구·거점·캐릭터 외형 후보를 만들고 채택할 때의 상세 기준은 `16_AI_입체픽셀_스타일가이드.md`를 따른다.
- 이 문서는 상위 시각 원칙을, 16번 문서는 형태·색·재질·조명·지역 적용·AI 제작과 채택 체크리스트를 소유한다.
- 16번 문서는 실행용 초안이므로 최종 캐릭터 방식, 해상도·필터링, 렌더러·후처리와 물 표현 등 기존 `[미정]`을 자동 확정하지 않는다.

## [제안]

- 기본 카메라는 높은 쿼터뷰 계열로 두고 Vista에서 제한적으로 구도를 바꾼다.
- 먼저 작은 시각 시험 구간 하나에서 기본 시점과 전망 시점을 함께 확인한다. 전체 월드를 꾸민 뒤 검증하지 않는다.

## [미정]

- 2D 픽셀 단면의 정확한 해상도, 보행·공격 프레임 수와 대각선 실루엣
- 투영 방식, 카메라 조작과 각도
- 화면 전체의 저해상도 렌더링 여부
- 텍스처 해상도와 팔레트
- 렌더러와 성능 기준

480×270 렌더링이나 모든 텍스처를 32×32로 만드는 과거 예시는 강제 규격으로 이관하지 않는다.

## [제안] 에셋 파이프라인

- 최종 게임 에셋과 생성 후보·편집 원본을 분리한다.
- 생성 결과는 크기, 방향, 피벗, 충돌, 실루엣, 재질을 확인한 뒤 채택한다.
- Meshy와 Higgsfield 등은 제작 도구 후보이며 게임 실행 의존성이 아니다. 이번 단계에서는 결제, 연결, 다운로드하지 않는다.
- GitHub에는 실행에 필요한 정본을, Drive에는 원본과 후보를 두는 방향이다.
- Git LFS의 사용 범위, 용량, 비용은 실제 에셋이 생길 때 별도로 정한다. 대형 생성 원본을 저장소에 일괄 추가하지 않는다.
